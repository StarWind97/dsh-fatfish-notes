分类的目的，是让下一次需要资料时少想一步。一个清楚的标题，加上少量链接，往往比层层文件夹更管用。

## 按任务命名

“启动不了”很难找；“文档站：依赖安装后仍无法启动”会留下更多线索。摘要写结论或使用条件，标签用于跨笔记本查找，例如“上手说明”“待补充”。

这册手册也用同样的方法：[项目上手说明](handbook-note:write)负责操作步骤，[会话转存](handbook-note:capture)保留问题的来由，[资料整理](handbook-note:materials)集中说明文件怎么放。

## 建立真正能打开的链接

在编辑器里插入已有笔记的链接。读者可以预览或打开，被链接的笔记也能在引用区域找到相关内容。

**试一试：**打开上面的“项目上手说明”，查看资料区的引用。这里的数量来自这些笔记之间的实际链接。

## 把小工具留在解释旁边

下面的 JavaScript 片段把资料文件名按名称排序，适合在编写交付清单时取用。代码块可以直接复制，缩进会保留。

```javascript
const files = [
  '项目交付清单.md',
  '阅读区宽度检查.csv',
  '部署说明.pdf',
];

const names = [...files].sort((a, b) =>
  a.localeCompare(b, 'zh-CN', { numeric: true })
);

console.log(names.join('\n'));
```

代码旁边要写清用途和输入条件。复杂脚本可以作为附件保存，不必让长代码挤满整篇笔记。

## 保留常用入口

- 收藏经常回看的笔记。
- 临时打开的笔记标签方便来回切换；结束 DSH 后不保留这一轮标签。
- 需要批量整理时进入多选，条目用于选择，再统一移动或处理。

先试着搜索“上手说明”，再从结果打开一篇。标题、摘要与正文一起提供线索，不必记住它原来放在哪一本。
