02 / CLARITY

“发虚”还有一个显示链路原因

源图清楚，Chrome 也已缓存正确的 32 px 图像；但当前应用窗口交给 Windows 的图标，更接近 16 px 图像放大后的结果。

补充 ICO 尺寸、换成 PNG 或 SVG 都未消除它。下方的临时原生加载实验保留了源像素，说明配色和清晰度需要分别处理。

查看试验结论与验证边界

什么已验证，什么仍待接入

  • 真实隔离 DSH 的正常入口重现了当前图标；本轮未修改其安装资源。
  • 独立复现实验使用与产品相同的 Chrome --app 模式与 favicon 声明。配色试图是实际 Windows 任务栏，不是网页模拟。
  • 9 组来源／配色／倍率试验；1.25 和 1.5 为浏览器强制倍率，系统 DPI 仍为 96，不能当作物理高分屏验收。
  • 临时直接给窗口提供 32 px 图标后，原生提取像素与源图一致；并不自动解决未来的重开、刷新和不同 DPI。
  • 正式接入需另行验证窗口身份、句柄生命周期、重开与刷新；本轮没有加入常驻进程或轮询。

推荐先选定配色，再把清晰度修复作为一个小范围接入任务。保持现有配色也可以独立改善清晰度。
