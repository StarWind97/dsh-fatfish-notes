# DSH 0.2.2-rc.3 兼容性排查与测试

状态：排查完成，实际加载未通过；适配方案待用户批准。用户于 2026-11-16 要求更新 DSH 后立即进行兼容性排查和测试。本轮授权为检查、隔离验证与记录；发现需要依赖升级或产品适配时，给出具体方案，批准后再修改。

## 目标与范围

- 核对实际安装桌面程序、运行内核和插件版本，避免把旧隔离宿主的结果当作新版结果。
- 验证当前候选能否在新版正常加载；能加载后检查主页面、独立窗口、会话侧栏、设置与明暗，以及阅读、编辑保存、附件、转存、导出和同步的受影响链路。
- 固定复查：公开接口能否完成文件接收、草稿附件登记、加入指定会话输入框、显示及移除、发送后读取。只看到内部实现或 addAttachments 不算条件具备。
- 不发布、不改变测试仓库名称、不修改日常 DSH，不先放宽兼容声明或绕过宿主检查。

## 方法、影响与取舍

先检查已安装新版及官方 rc.1→rc.3 变化，再使用 `.dsh-home/pure-001/` 内原隔离资料和已有候选包验证。启动前保存测试配置基线；临时脚本、日志与截图留在忽略目录。产品源码和依赖保持原样。

如果版本栅栏阻止加载，应先报告真实失败和后续适配影响；不将只针对 rc.1 的离线测试称作 rc.3 功能通过。若可加载，使用已有测试资料而非改动日常资料，不主动发送模型请求。

本轮主要更新本规划、开发入口及验证记录。预计为一轮集中排查；遇到接口变化再单独估算开发量。

## 风险与恢复

新版宿主可能自动更新隔离运行组件；记录前后版本、备份测试 profile 清单和相关配置。保留已安装候选包及笔记资料。测试窗口可按已授权关闭；不清理 Cookie 或其他认证数据。若宿主迁移导致不兼容，不盲目降级打开已迁移资料。

## 验证与交付标准

1. 实际版本、候选来源和工作区基线可追溯。
2. 加载结果以真实宿主日志和界面为准；分清静态审查、离线测试、实际交互及未覆盖部分。
3. 新增公开附件能力给出类型和实现依据，必要探针限测试会话；未发送模型请求时明确发送后读取未验。
4. 测试完成关闭自建验收进程，保留旧评审网页，提供原隔离启动入口及兼容结论。
5. 本轮如涉及实际读取性能，常用操作测五次，报告资料规模、中位与最大；加载被阻止则不编造性能结果。

## 后续适配方案（待批准，不在本轮直接实施）

推荐以用户当前 **0.2.2-rc.3** 为新基线，保持现有产品功能，分三轮完成：

1. **依赖与合同核对**：对齐 package.json、锁文件中的 DSH 开发依赖/peer、engines 及兼容声明；Cordis 仅在新合同确实要求时变更。先编译确认全部类型，再修复被新版改变的接口调用。不能先只改兼容声明就宣布支持。新版输入框原生附件仍延期。
2. **适配与回归**：必要源码修改限 `src/client/` 宿主注册/输入接口与 `src/host/` 会话、文件、模型桥接，以及相应测试。按实际发现修订本规划，非兼容所需的新功能或数据格式迁移另行确认。依赖变动按第三档执行类型检查、构建、全量回归、打包与安装文件核对。
3. **真实隔离验收**：主界面、独立窗口、会话侧栏；设置共享与既有明暗规则；编辑、自动保存、双窗口刷新；正文/补充区图片与文件粘贴拖入，尤其检查宿主新增全局粘贴不会重复接收；旧测试会话转存及材料、PNG/PDF/Markdown 下载；指定私库同步和重启读回；菜单在窄屏与缩放时的定位。阅读与切换各至少五次，仅报告 rc.3 当前测量，不与不同宿主的旧样本冒充严格前后对照。默认不自动发送新模型请求，相关未测边界单列。

### 方案取舍

- **直接适配 rc.3（推荐）**：与当前用户宿主一致，验证矩阵较小；不承诺新候选继续支持 rc.1。
- **同时声明 rc.1—rc.3**：需要保留并分别测试两个实际宿主，还需处理跨版本合同差异；当前没有明确需求，先不增加维护成本。
- **仅放宽版本声明/允许不兼容运行**：不能证明接口正确，不采用。

### 风险、恢复与交付

主要风险来自宿主会话事件、输入与扩展合同变化。本轮不规划笔记格式迁移；若确需迁移则先另行确认。适配前保留 main 基线和旧候选，隔离配置另存；代码可通过新增回退提交恢复。由于 rc.1 包在 rc.3 被阻止，单纯退回旧插件不能恢复新版宿主内的体验；若回退宿主，必须单独确认并配合对应测试资料备份，不自动降级日常 DSH。

工作量预计为一轮中等规模兼容适配，具体以新类型检查结果调整。交付更新后的规划与验证记录、未发布候选、可用隔离入口；按用户要求提交后推送核对，不创建 Release、标签或市场更新。macOS、两台物理设备及模型实际发送仍需明确区分。
