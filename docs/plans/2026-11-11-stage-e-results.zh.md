# E 阶段交付与集中体验

状态：2026-11-11，E1—E3 已完成开发、自动测试与隔离验收，等待用户集中体验。正式发布仍为 0.8.0，本轮不发布、不更新市场、不启动 F。

## 交付范围

- DSH 右侧「会话笔记」：本会话来源、查找并关联、解除/撤销、阅读与原地编辑、自动保存、完整窗口入口；三处同篇编辑保护共用。
- 工作区默认笔记本：新建或指定已有本，转存仍可改选；未分组新建普通本；归属可修改，默认映射留本机并按仓库隔离。
- 保存与导出共用图片/普通文件选材，包含用户上传和 AI 正式交付文件。复制转存当时的文件内容，原文件以后变化不影响已保存副本。
- 「引用到当前会话」：单篇保存版本与所选材料复制到 DSH 管理的位置，输入框保留原文并加入读取说明，支持撤销，由用户发送。没有伪装成原生附件栏。
- 真正的 Web Worker 解压、解析和编码；分块传输、进度、收起后继续、有效取消。取消旧批次/整库累计体积封顶，同步及 ZIP 导出改为按文件/分块处理。
- 当前文件和 Git 历史占用统计、1/5 GiB 提醒；统一单文件、内嵌图片、数量和渲染保护。

实现与限制以[产品设计](../notes-design.zh.md)及[操作指引](../user-guide.zh.md)为准，原[实施方案](2026-11-10-stage-e-implementation.zh.md)保留目标与验收依据。

## 怎样集中体验

使用项目的 [Open-Fatfish-Notes.cmd](../../scripts/Open-Fatfish-Notes.cmd)，进入隔离资料。日常 DSH 未修改；旧 0.8.0 不要接回已经升级格式的测试库。

1. 打开工作区「肥鱼 E0 普通文件补验」下的会话「E0 普通附件与生成文件」，点击会话顶部书本图标「会话笔记」。
2. 在「从本会话保存」中打开「从会话继续 · 文件与笔记」；试阅读、编辑标题/摘要/标签/正文，再切回会话。修改自动保存。
3. 到「查找并关联」搜索其他笔记，关联后在「关联的笔记」查看；解除后可撤销。来源组不会因解除手动关系消失。
4. 从会话下方「保存到笔记」或侧栏保存入口选择范围、笔记本及文件；工作区默认本为「E 阶段 · 会话资料」。AI 建议默认沿用原有选择，验收中可关闭以避免消耗。
5. 阅读笔记后点「引用到当前会话」，选择材料并加入说明。确认原输入还在，试 Ctrl+Z；验收脚本没有自动发送消息。需要让模型使用时，由你填写要求并发送。
6. 在笔记库「导入 / 导出」体验扫描、目标本、进度和取消；退出应用会停止后续处理，已经保存的笔记保留。测试数据含大文件，请勿把同一批反复全部导入。

实际截图图册在 `output/playwright/stage-e/index.html`，所有画面来自隔离宿主，不是静态样稿。开发包和证据保存在忽略目录 `.dsh-home/pure-001/stage-e/`，可重复打开的入口仍使用现有脚本。

最终候选为 `dist/fatfish-e-27573d5efd60.tgz`，SHA-256 为 `27573d5efd604693d65dc16f1d6f5da8d1974ab65feb566ad5e1939d2a79f280`；Desktop 与 Web 安装后均逐项核对 166 个包文件一致。候选保留 0.8.0 包版本以供本机开发验收，不能仅凭版本号区分正式包与此候选；对外发布时另定新版本。

## 响应与容量

每批均通过正式 ZIP 导入入口，不通过直接写文件绕开保存。225 MiB 的扫描/完成为 6.3/63.3 秒；315 MiB 为 9.2/102.1 秒。导入时切到会话并输入各 5 次，分别中位数/最大值 51/151 ms、49/210 ms。50 ms 界面定时器的最大间隔为 402/319 ms，没有观察到持续多秒整页卡死；这不是键盘输入延迟的精密测量。

Desktop 各 Electron 进程合计工作集：开始约 631 MiB，中位约 994 MiB，最高约 1215 MiB，结束约 977 MiB（84 次采样）；包含宿主、界面、Host 和 Worker，不能当作插件独占内存。两批没有持续按累积文件总量增长的常驻缓冲，但仍有单文件与运行时峰值。文件为可压缩合成字节，用于容量/完整性检查，真实视频网络同步速度不可从此推算。

常用操作复测沿用同一 B—D 文章、窗口尺寸、浏览器和“内容显示后再等两帧”标准，各 5 次，单位 ms（中位 / 最大）：

| DSH 内 · 切回原本 | 154 / 197 | 229 / 414 |
| DSH 内 · 长文 | 161 / 256 | 320 / 344 |
| DSH 内 · 普通笔记 | 167 / 216 | 232 / 278 |

E 后全库增加了会话材料与大文件，测量时另有回归/后台同步，因此这组是功能扩展后的响应观察，不能当作严格同规模性能优化结论。主界面/独立窗口常用热切换均在 0.5 秒内。侧栏读取 5 次为 341、545、333、321、359 ms，中位 341 ms、最大 545 ms（`final-ui.json`）；新侧栏无旧版对照。首次打开只有各 1 次：DSH 内 10651 → 418 ms、独立窗口 1317 → 1293 ms；热状态和后台同步不同，不据此承诺启动提升。记录为 `release080/e-before.json`、`e-after.json`。

## 未覆盖及回退

- 未测 macOS、两台物理设备、WSL/远程会话文件路径；没有让模型解读所有文件格式。普通文件提供保存/下载，不提供播放。
- 官方原生输入附件登记入口仍不完整；已复查当前 0.2.2-rc.1 的公共声明，不调用内部 `createDrafts`。下次宿主升级和 F 规划继续主动核查。
- 常见规模之外的极端数量、5 GiB 实库和低内存设备未作流畅承诺。超大图片渲染保护不等同于文件保存限额。
- notes manifest v3 保护新关联、来源选材与容量规则。参与同库的实例需一致升级；回退需恢复升级前笔记/配置备份及对应包，不能只降级到 0.8.0 写新数据。远端历史正常保留，不强推重写。
