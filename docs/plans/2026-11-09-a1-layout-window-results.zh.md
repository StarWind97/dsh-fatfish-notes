# A1：三栏样稿与独立窗口补验

状态：2026-11-09 已完成技术补验和交互样稿，**用户随后确认布局，已接续 A2**，实际结果见 [A2 交付](2026-11-09-a2-layout-results.zh.md)。本文保留 A1 当时的技术证据与取舍，属于[阶段 A 专项](2026-11-09-adaptive-layout-and-independent-window.zh.md)，总体阶段以[主规划](2026-11-09-product-iteration-roadmap.zh.md)为准。

结论：可以继续采用同一 DSH 服务加浏览器应用窗口的路线。稳定的本机入口能覆盖 DSH 重启换端口；Chrome、Edge 的打开和复用通过。Windows 不保证后台程序每次都能抢到前台，正式实现应尝试唤回、失败时给出轻量提示，不为此改系统设置或反复新开窗口。三栏样稿可开始验收，正式同篇编辑保护仍须在 A3 完成后才开放双窗口写入。

## 1. 实际验证及边界

使用 Windows / Node 24.21.0 / DSH 0.2.2-rc.1、隔离 `release12-desktop`、指定私库 `StarWind97/dsh-community-private-test`。原型复用 0.7.0 后端与现有 React 组件，没有改生产源码、DSH 安装文件、日常资料或账号凭据。

## 2. 稳定入口的最小方案

原 DSH Web 地址会在重启时变化，浏览器恢复记录按来源隔离。采用**原 DSH 进程内的 loopback HTTP 入口**，与已有笔记服务共享应用对象和存储；不是另起常驻代理或第二个写入服务。DSH 完全退出时此入口随之停止。

原型使用固定测试端口，并仅将笔记路径转发给原 DSH 服务来证明生命周期。A4 正式实现优先让入口直接调用现有应用的 HTTP handler，减少内部转发；端口按隔离资料首次选择并持久化，重启复用。端口被占用时明确提示，不静默换来源导致恢复稿失联，也不自动结束未知进程。

入口仅提供插件页面和必要的笔记接口，复用 loopback、Host、Origin、sec-fetch-site 及仓库身份校验。浏览器资料独立存放于本机控制目录；不复制 DSH Cookie，不向浏览器发送模型或 GitHub 凭据。打开请求只允许已检测的 Chrome/Edge、固定插件 URL 和专用资料目录，不能传入任意命令、可执行路径或网址。

窗口登记仅存本机；使用进程 ID、启动时间和窗口句柄避免误认其他进程。重复打开复用现有窗口，尝试恢复最小化状态与前台显示。被系统拒绝时保持窗口和笔记请求，不循环创建窗口；提示用户从任务栏切回。此限制不妨碍 A2 的共享布局开发。

## 3. A3/A4 的最小协调契约

以下是待实施约定，**不是原型已经实现的保护**。沿用稳定 ID、修订和仓库身份，不改 notes manifest，不把窗口心跳或阅读状态提交到 Git。

| 能力 | 最小字段与约束 |
| --- | --- |
| 窗口登记 | `repositoryId`、`windowId`、`surface`（embedded / standalone），返回 `serviceEpoch`。进程重启产生新 epoch，旧请求必须重新登记。只支持一个独立窗口。 |
| 状态读取 | 返回内容变化序号 `changeSeq`、实际生效主题、当前笔记的编辑归属及必要的打开/交接请求。不携带模型凭据或大段正文；有变化且处于阅读态才刷新内容。 |
| 按篇编辑资格 | 以仓库和 noteId 为键，返回随机 `leaseId`、`serviceEpoch` 和有效期；保存携带资格与既有 `expectedHeads`。续期失败后停止新的提交，保留恢复记录。心跳/过期时间在 A3 竞争测试中确定，不建设跨设备锁。 |
| 请求交接 | 新窗口请求；原窗口先结束组词/附件处理并保存，成功后释放，再授予新窗口。新窗口读取最新修订后进入编辑；失败或取消保留原位置和内容。不先强抢再补保存。 |
| 全写入入口 | 保存、元数据、图片/附件变更、删除恢复、批量、笔记本移除和异步采用均在公共写入边界核对占用及版本。工具等没有窗口资格的入口不能绕过占用；批量操作先检查目标集合。 |
| 迟到请求 | 编辑资格撤销或 epoch 变化后，旧窗口请求不得落盘；在写入临界区核对，交接等待已有写入完成。错误只显示简短的刷新/交接提示。 |
| 恢复稿 | 按仓库与窗口来源分槽，保留生成它的窗口标识、版本基线和内容。稳定来源可跨 DSH 重启读回；恢复前重新登记、取得资格、核对最新版本，已有更新时不能静默用旧稿覆盖。 |
| 不同笔记 | 两个窗口可分别编辑不同笔记；新建与会话转存继续可用。不能用「禁用主窗口全部写操作」替代按篇保护。 |

本轮恢复原型仍沿用现有恢复策略，尚未加入 lease。对正式版的恢复验证必须包含其他窗口已有更新、过期原稿和交接后的迟到保存，不能只复用本次单写者成功结果。

## 4. 样稿与建议参数

样稿源码和打开方式见 [A1 样稿说明](../prototypes/a1-layout/README.md)。生成的 `output/playwright/a1-layout/index.html` 为可直接打开的单文件，不需后台服务。使用独立示例内容，浏览器本机保存，不连接真实 DSH/GitHub；切换另一浏览器不会带走这些演示修改。

复用现有 `NoteEditor`、CodeMirror、章节目录和样式。新增样稿只负责笔记本栏、列表、宽度和入口布局；笔记本管理仅展示入口关系，编辑占用与交接为明确标注的模拟。正式版主题仍跟随 DSH，样稿的深浅色开关只是验收工具。

| 项目 | 本轮建议，待用户验收 |
| --- | --- |
| 笔记本栏 | 初始 196 px；164–260 px 可调，默认本标记、计数和管理入口。 |
| 笔记列表 | 初始 312 px；240–440 px 可调，正文摘要继续显示；空间不足临时收窄，保留原偏好。 |
| 正文空间 | 优先保留约 460 px；已有标准宽度/全宽和目录规则继续复用，不按屏幕比例无限拉宽侧栏。 |
| 三栏切换 | 测量插件实际内容区。首次达到 1140 px 默认展开，已展开后低于 1100 px 自动收起；中间缓冲区避免反复切换。 |
| 偏好 | 宿主内与独立窗口分别记忆。手动收起后拉宽仍保持收起；原本想展开、暂时变窄后再拉宽则恢复展开。 |
| 管理入口 | 保留已有「笔记本」选项卡，导航栏中也可直达；不是再造第二套管理功能。 |

专项交互检查通过：宽屏默认、手动折叠记忆、键盘与鼠标调宽、两种窗口偏好分离、窄屏下拉及选本、模拟交接、实际 CodeMirror 编辑、示例自动保存及刷新读回、深浅配色；检查期间没有 HTTP 请求或页面异常。样稿及其引用的客户端通过类型检查，样稿完成构建；未修改生产保存逻辑，因此没有重跑 0.7.0 全量回归。
