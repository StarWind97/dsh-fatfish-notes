# 自动保存与双向同步

状态：2026-11-05 用户批准实施。

## 体验

- 标题、标签、摘要和正文自动保存到本机；编辑态保留撤销重做。原始会话素材不变。
- 「完成编辑」返回阅读态；切换笔记、会话或插件、刷新、正常关闭后回来，也从最新内容的阅读态继续。
- 使用本机恢复记录保护尚未收到保存回执的编辑，自动恢复，不增加草稿管理界面。保存失败和图片尚在导入时才提示用户。
- 本机保存与 GitHub 同步分开。快速编辑合并上传；完成编辑、离开、重新打开、恢复网络及手动同步都检查双向更新。前台打开时每五分钟检查远端。
- 顶栏显示同步中转圈、绿色对号「已同步」、必要的简短异常提示；点击进入同步设置。不把鉴权错误一律解释为网络问题。

## 实现取舍

采用短延迟自动保存和连续输入的最长保存间隔，避免依赖退出时才发出异步请求。浏览器本机恢复记录按仓库隔离，保存回执确认后清理；返回同一宿主页面时自动恢复。远端更新不直接替换正在编辑的内容，保留现有双版本冲突处理。

修改客户端编辑控制器、生命周期、状态栏、相关文案及同步调度；沿用远端数据格式和身份校验。新增恢复记录仅存在本机。不开发正文 AI 整理，不发布新 Release 或 npm。

工作量为中等规模跨模块修改，主要投入在保存生命周期与真实宿主验收，无新增依赖。

## 验证与交付

保存与同步按第三档检查：类型、构建、全量回归；隔离 Web/Desktop 验证输入、撤销、中文输入、图片、刷新、切换和正常关闭重启；指定私有测试仓库验证双向同步。记录实际覆盖和限制，提供截图与体验入口，中文提交并同步 main。

风险集中于异步保存回执、离开页面和同步期间的并发编辑。测试覆盖这些边界；未收到回执前保留恢复记录，保存失败不静默丢弃。必要时可新增回退提交还原客户端与调度，不改写历史或删除笔记。
