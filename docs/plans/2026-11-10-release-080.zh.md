# 0.8.0 集中发布前准备

2026-11-10，用户体验性能优化后认为可以，授权按原规划准备新版。此项承接[主规划](2026-11-09-product-iteration-roadmap.zh.md)的 A—D 统一发布节点；准备完成后交用户确认正式发布。

准备已完成：候选包和发布材料就绪，最终检查、实际安装及同步已核验，当前停止在正式发布确认处；详见[审核记录](../releases/0.8.0/review.zh.md)。

## 范围与取舍

将自适应三栏、独立窗口与编辑保护、收藏和查找、历史恢复和批量整理、文章关联和模板，以及读取性能优化合并为 0.8.0。新增功能较多，采用次版本更新，不拆成多个补丁版本。E 会话侧栏、F AI 输出不在本次范围。

- 更新包与锁文件项目版本，不升级依赖、不再增加功能或改变数据格式。
- 完善中英文说明、用户指引、发布说明、升级边界和实际截图；准备市场条目及 PR 正文，正式市场条目仍指向已发布的 0.7.0。
- 执行发布级验证、打包、核验包内容及安装文件，交付候选包、摘要、验证结果和体验入口。工作量为一次发布收尾。

## 验证与回退

按第三档依次运行类型检查、构建和全量回归，避免构建与产物测试并行。使用公开 0.7.0 包的存储实现创建空库及含图文附件的旧资料，交给候选版读取，检查旧内容和新增收藏/模板字段、历史以及再次打开。另在项目隔离 DSH 实际安装最终候选包，检查版本、内容、双窗口保存、指定私库同步、重启读回及常用操作响应。

主要风险是新增修订字段不能由旧版识别，以及多窗口恢复稿未保存时退出。保留旧包和隔离资料备份；同一私库的实例一并升级。回退代码可新增回退提交；需要运行旧版时必须恢复相配套的资料备份，不能直接用旧程序继续写新版资料。准备阶段不修改用户日常 DSH，不清空远端历史，不建立新的兼容框架。

候选包与已体验内部包的运行代码应一致。其他已验证操作沿用 A—D 和性能专项证据；最终包抽查实际入口，不为截图重复整轮测试。Windows / DSH 0.2.2-rc.1 是已验证环境，macOS、两台物理设备和大型真实库不声明覆盖。

## 交付停止点

准备完成后提交同步 main，展示 0.8.0 候选包及实际验证结果，请用户确认。此阶段不打发布标签、不创建或上传 Release、不提交市场 PR、不发布 npm。正式获准后发布 GitHub Release，匿名下载并安装公开包核验，再更新原市场条目；不重复申请收录。

审核材料与最终检查结果见 [0.8.0 发布审核](../releases/0.8.0/review.zh.md)。
