## 2. 目标与边界

目标是把已评审的外观和工作方式落到真实 DSH 中，服务查找、整理、编辑、暂存和复用资料。主界面、独立窗口、会话侧栏属于同一次交付范围。

采用现有 React / CodeMirror / Markdown / CSS 架构；建立一套共享工作区与阅读组件，由有限布局变体控制位置和形态。八套主题不是八个应用，也不只是八种颜色。不把逐轮叠加的演示脚本直接搬入产品。

不做缩略图、自由拖拽面板系统、标签分组/拖动重排/跨次恢复、第三方主题市场、任意远程 CSS、分页图片、网页导出、会话 AI 新建/修改笔记，不升级 DSH、不发布。本轮不改变笔记文件格式、仓库身份规则和 Git 同步协议。

## 3. 最终外观结构

### 3.1 八套界面主题

| 编号 | 名称 | 正式实现保留的差异 |
| --- | --- | --- |
| 01 | 秩序工作台 | 连续三栏、规整边界、清晰紧凑的工具区，作为默认 |
| 02 | 柔和分区 | 独立圆角面板、柔和层次；默认紧凑，可调整密度 |
| 03 | 横向导航 | 顶部笔记本导航，左列表与右正文；笔记本溢出可访问 |
| 04 | 侧轨资料台 | 可展开的紧凑导航轨；资料位置仍服从用户设置 |
| 05 | 墨线书房 | 书页式排版与细线层级；导航可展开、固定，不牺牲找笔记能力 |
| 06 | 目录树工作室 | 笔记本和笔记合并为分组树；只加载已展开组的必要列表页 |
| 07 | 浮岛桌面 | 独立工作面板、底部全局导航；可固定导航，避开宿主状态区 |

全部覆盖阅读、编辑、笔记本管理、设置、空白/错误/回收站及弹窗。独立窗口和侧栏按实际空间适配，不机械挤入完整三栏。切主题不能丢失草稿、重建编辑器、清空搜索或触发资料同步。

### 3.2 配色、对比与设置

- 保留十种：DSH 原生、柔紫、青绿、雾蓝、暖砂、莓红、石墨、澄蓝、松青、墨白。
- 原生标准对比直接使用宿主语义颜色，跟随其浅深与后续主题变化；不靠截图色值长期模拟宿主。
- 其余配色控制正文、功能区、浮层、边界、文本与交互状态；全部提供浅深模式。柔和/鲜明属于对比定制，不称为与宿主颜色完全相同。
- 清楚区分选中、悬停、键盘焦点。选中可用足够明显的背景和轻层次，不强制粗边框，也不添加“当前”字样。
- 布局、配色、阅读、工作区四组设置互相独立。切换主题不覆盖用户已经选择的配色或资料位置。
- 外观偏好保存于本机浏览器/窗口环境，支持同源界面更新和恢复默认；不进入 Git。不同客户端暂不跨设备同步外观。已有列宽、全宽等有效偏好尽量保留；无新偏好时使用新默认，未知值回到安全默认。
- 默认排版为现代清晰。选择书页主题时可提供其排版预设；显式选择的阅读预设优先，切主题不暗中改字体。

### 3.3 正文与代码

正文先提供现代清晰、书页、混排三种预设；默认无衬线，中文和西文回退明确。17–18 px 正文、约 1.8 行高、740 px 舒适宽度作为实机起点；窄侧栏按实际内容空间调整，用户可选全宽。最终数值由同内容实看修正，不把原型值当不可变规范。

优先使用宿主/系统字体；自定义字体只使用已有或许可清楚、体积可控的资源。仓库已有 Noto Sans CJK 的 PDF 字体，不重复引入整套中文字体，也不让阅读首屏等待大字体文件。代码可提供 Cascadia 的 Light / Regular / Medium 及系统等宽回退；计划以 Regular 14 px 起步。具体字体分发先核对许可、实际包增量和离线可用性。

代码方案比较：

| 路线 | 取舍 |
| --- | --- |
| 仅等宽排版 | 成本最低，但不满足用户选定的精细高亮 |
| 阅读也用现有 Lezer | 依赖增量较低；早期只验证 JS/TS，不能据此宣称全部语言支持 |
| Shiki 阅读 + 现有 CodeMirror 编辑 | 推荐；尊重用户已选视觉效果，编辑沿用适合输入的增量解析，避免每次键入运行整块 Shiki |

Shiki 先使用细粒度模块和 JavaScript 引擎；阅读与 PNG 共用输出。按需加载、实例复用、按正文/语言/主题缓存；超长或失败时完整展示可复制原文，不阻塞正文出现。常见语言的计划范围为 JS/TS、JSON、Python、Shell、YAML、HTML、CSS、SQL；编辑器的对应语言支持需逐项核验，不用假分色冒充。未知语言回到纯文本。依赖已在本轮授权范围内锁定：Shiki 4.6.0 及对应 CodeMirror 语言模块；实际增量见分轮记录。

保留缩进、空格、换行、Tab；只做显示，不自动改写或格式化原代码。提供语言标签、复制、折行/横滚与可选行号；默认不显示行号。搜索标记、复制结果、明暗颜色、中文注释和 PNG 一起验收。

官方依据：
- https://shiki.style/guide/best-performance ：实例复用、细粒度导入及按需加载。
- https://shiki.style/guide/regex-engines ：可使用 JavaScript 引擎，不必默认引入 WASM。
- https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/web-styling.md ：功能插件消费共享主题角色。

早期网页实验的 Shiki 热高亮 239 行代码中位约 48.7 ms，未含 DOM/绘制或实际宿主开销，只能作为需要控制同步任务的线索；本轮正式试验必须重测。

## 4. 资料、目录与导航

### 4.1 资料区域

- 默认底部，点击把手打开；自动模式下点击正文/外部或 Esc 收起，在面板内操作、复制、下载时不误收起。不使用任意倒计时。允许固定，固定后不自动关闭。
- 收起时保留可点击把手和明确计数，例如“资料 2 · 引用 3”。没有资料时仍可显示轻量入口，编辑态可直接添加；不占用空的大面板。
- 位置可选底部或右侧；右侧支持目录/资料页签或上下分区。目录和资料都有直接可见的工具栏入口，不先点目录才能发现资料。
- 只移动共享展示，附件/引用数据不因开关或换位置重复读取、全库解析或扫描。
- 文件名（含后缀）和大小同排，不重复“文档/PDF”等类型文字。普通文件图标可以表达类别。窄时转单列、名称省略但保留后缀和大小，完整名称可查看。
- 宽时附件及引用充分横排；目录挤压、拖窄窗口、右侧 240–320 px 或侧栏 360–520 px 时根据资料容器宽度重排。底部固定面板约不超过阅读区域三分之一高度，过多内容内部滚动。
- 附件与引用有独立区域、标题及层次，视觉上不同于正文。引用计数沿用准确总数；未知/失败不伪装成零。零引用的引用清单隐藏，有引用时在资料面板内默认展开。

### 4.2 笔记标签与联动

- 本次浏览打开的笔记形成可关闭标签；同篇去重，恢复各篇阅读位置；关闭当前标签选相邻项，最后一个关闭后显示自然空态，不删除笔记。
- 按窗口、仓库及入口维护内存状态；在本次运行中返回同一入口可继续使用，关窗/重新启动后不恢复标签。实际宿主卸载/重载生命周期先试验；刷新或插件重载清空不影响已保存笔记。保留既有“最后阅读笔记”行为，它不等于标签恢复。
- 主界面、独立窗口、侧栏复用标签逻辑，各入口维护自己的打开记录，不新增跨窗口标签同步。
- 切换成功后，标签、正文、列表选中和所属笔记本同时更新；必要时展开目标组、定位分页和滚入可视范围。移除会隐藏目标的冲突筛选，明确显示新的所在笔记本。
- 切换失败、输入法组合或未完成保存时，保持现有正文与选择，不出现“标签已变，正文没变”。关闭标签同样通过保存检查。
- 一次仅挂载当前编辑器，不为标签同时加载多篇正文；主题切换、导航固定或资料开合不重建编辑器。保持撤销历史、光标与未提交输入。
- 多选状态继续整行选择；不因新增标签恢复点击标题打开的旧问题。删除/回收站/恢复/同步变化时修正已打开标签。

## 5. 弹窗、快捷键与导出

弹窗统一视觉、间距和按钮规则。宿主给足空间时采用更宽的双列/分组布局，普通选项尽量完整显示；小窗口改为单列，长材料局部滚动，标题与操作区可达。实际宿主能否跨插件区域显示需实测，不以模拟整页宽度承诺。导出、转存、笔记本操作、设置和失败状态一起检查。

阅读保留 Home / End / Page Up / Page Down，并确保焦点在输入框、代码横滚、弹窗时不会被全局阅读键抢走。快捷键按常用任务与标准可访问操作统一整理，不给每个主题、面板、配色等低频功能添加专用组合键；检查与 DSH 现有快捷键冲突。

PNG 继续使用阅读组件与已保存修订，补齐字体、字号、行高、代码高亮、配色和素材选择等外观上下文。当前阅读宽度包括全宽及目录挤压后的真实正文宽度；目标未显示时使用明确的默认 740 px，保留现有预设。超出宽度/画布预算时明确提示，不能悄悄缩成默认宽度，也不分页。导出不含工具栏、标签栏、复制按钮等操作控件。

资料面板的位置和开合不决定导出是否遗漏附件：依照导出选择，将补充附件连续排在正文之后；引用回链按现有规则不进入图片。不能直接截图整个工作区，也不能让资料面板滚动条截断资料。固定保存修订，原始会话资料不得覆盖已编辑正文。

PDF 保留现有连续内容和分页文档用途，跟进必要的字体、字号与内容完整性验证；本轮不重写为截图式 PDF，也不承诺与阅读界面逐像素一致。PNG / PDF 不打包附件原件，Markdown 资源包负责完整带走文件。原图仍为原文件下载。

已完成的内容只做受影响回归：上传文件原位链接、标题命名压缩包、图片/链接互换、多选、引用计数、阅读按键、四类导出成功关闭与轻提示、失败保留和生成可取消；不重复开发。会话独立导出按钮保持移除，网页导出只留候选。

## 8. 性能、验证与验收

### 8.1 性能要求

- 换主题、配色、开合资料、固定导航：不发起笔记数据请求、不触发同步、不解析全库；常规面板响应目标约 100 ms 内。
- 普通笔记热切换目标约 300 ms 内出现正文，首先不劣于同环境基线；首次高亮和字体加载单独记录，不能把高亮结束当正文出现的必要条件。
- 树形只加载展开组和必要分页，关闭的标签不挂载正文。缓存有版本/主题/仓库失效规则和容量上限，跨库不混用。
