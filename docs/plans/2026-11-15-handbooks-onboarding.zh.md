## 1. 目标与完成标准

用户手册同时承担三件事：让初次打开的人愿意阅读和记录；帮助完成第一项真实任务；用自身的图文、代码、清单、链接与资料展示笔记的表达能力。美观是交付标准，不能只在功能通过后补一张封面。

采用两本手册：

- **开发手册**：面向用户与 Agent，放技术实现、设计取舍、开发操作、问题调查及验证索引。正式事实仍以源码、项目规划和实际记录为准，手册链接这些依据，不另写一套互相矛盾的状态。
- **用户手册**：面向使用者，说明具体任务如何完成，也是一组可阅读、编辑、复制和导出的真实笔记。正式初始化只提供这一册。

这里的“两本”指两本手册笔记本，每本可包含多篇短笔记；不是把全部内容挤成两篇长文，也不是限制用户只能创建两个笔记本。产品原有默认笔记本继续承担日常收集。

本轮不扩展编辑器格式、主题引擎或 AI 写笔记，不开发网页导出、分页图片、视频教程、交互导览系统、阅读进度、自动手册更新或新模板系统；不删除旧验收资料和用户笔记，不创建日常用户的模拟 DSH 会话。

## 3. 视觉与内容设计

### 3.1 推荐方向

采用温暖、自然的配图与清晰的现代排版。功能区域跟随 DSH 原生配色和用户主题；正文通过构图、图片比例、内容层级、段落节奏和准确命名形成品质感。手册不锁定专用配色，不要求用户换主题才能好看。

- **首页首屏**：在常用桌面窗口下能读到标题、简短说明、主要视觉与进入内容的线索。避免巨大的图片把全部实际内容推到屏外。窄侧栏允许自然纵向展开，不强行塞满同屏。
- **配图**：准备少量一致风格的 GPT 生成配图，围绕真实知识工作、阅读和创作场景。使用宽幅、适合裁切的构图，避免假代码、乱码、虚构界面与失真的办公物件。图像源与提示词保留，发布用尺寸单独优化。
- **操作图**：需要解释位置时截取真实插件界面，减少截图中的重复留白。基础操作优先文字＋实际操作，不能每个按钮都堆一张图。截图注明适用版本，数量适度以降低后续维护。
- **文字**：使用具体标题与自然表述，删去宣传套话和“验收成功”式占位内容。示例中有问题、做法和边界；不同篇目不机械套用同一个结构。
- **排版**：复用当前默认字体、代码 Regular、行高和阅读宽度。表格尽量三列以内；长代码、长文件名在窄栏也能阅读。Markdown 标题与系统笔记标题不重复。
- **资料**：PDF、代码或 CSV 等附件服务于文中的任务，格式正确、文件名自然、显示真实大小；不随册附带与任务无关的大文件。

首页、综合示例页和带资料的页面先在实际隔离插件中打磨，再扩展整册。网页可用于汇总截图和反馈，产品效果以宿主内、独立窗口及会话侧栏的实际渲染为准；不重做现有主题评审网页。

### 3.2 用现有功能完成演示

- 链接必须指向实际存在的手册笔记，引用数量由系统真实计算；用户可预览、打开和返回。
- 图片与下载链接通过既有转换入口演示；正文和补充资料使用正常归档资源，不制作只能看的假卡片。
- 代码块标注正确语言，复制结果保留缩进且可用。代码不会为了配色而伪造无意义标记。
- 当前阅读态任务清单没有直接切换复选框的写入逻辑；说明按现有编辑方式修改，不暗示可在阅读态直接打勾。本轮不顺带新增该功能。
- 首页中的行动入口用真实笔记链接及现有控件，不画无法操作的“开始体验”按钮。
- 模拟会话用于说明自然工作场景，来源性质在适当位置说明，不冒充客户记录或模型测评。随包手册不注入 DSH 会话、不伪造可跳回的用户历史；“原始素材”通过用户真实转存学习，隔离样例继续用于实际验收。
- 指导用户先复制示例页再动手；原手册仍允许正常编辑、移动或删除，不增加特殊锁定或只读身份。

## 4. 体积与加载预算

不再采用 0.5–1 MiB 的硬约束。**初版按新增安装包约 2–5 MiB 规划，这只是估算和复核点，不是压低视觉质量的硬门槛。** 必要时可超出，记录实际新增字节、增加的内容价值和加载结果，再判断取舍。

当前候选安装包实测 15,901,447 字节（15.16 MiB）；前序 12 篇 Markdown 合计约 20.5 KiB，工作台原 PNG 约 2.12 MiB。主要体积来自图片，不能把文字说明当作包体负担的主要来源。不同格式压缩效果尚未试验，不承诺预计缩小比例。

实现时分别记录安装压缩包增量、解包后素材大小、初始化写入与首次同步资料量；不能用其中一项冒充另外几项。

- 生成原图和编辑源保留在开发资料中，随包只放经目视验证的展示版本。
- 照片按清晰度选 JPEG/WebP，界面与线图按文字锐度选择合适格式；不为了更小而把小字和细节压糊。
- 同一资源只存一份并复用，归档后用现有资源机制引用；图片不塞进前端入口脚本，不增加专用字体或渲染框架。
- 当前正文支持图片懒加载，手册沿用已有路径。手册内容在需要时读取，普通启动、切换其他笔记不应扫描或解码整册图片。
- 不依赖外网图床；完成初次接入后，手册图文可离线阅读。首次联网接入规则保持不变。

## 5. 首次初始化和后续使用规则

| 情况 | 预期行为 |
| --- | --- |
| 插件创建全新专用私库 | 初始化中加入一次用户手册，首个可阅读页面进入首页 |
| 首次连接已有专用空库 | 先取回并验证远端；确认没有笔记、回收站、删除或已提供手册的记录后，才自动加入 |
| 本机尚空、远端有内容 | 恢复远端原资料，不把本机暂时为空当成新库 |
| 已有笔记或历史的库升级 | 不自动加入或更改分类；通过手动入口获取手册 |
| 用户修改、移动或改名 | 保留用户版本，不因重启、升级或换设备覆盖 |
| 用户删除手册或清空库 | 不自动重新生成；保留手动获取途径 |
| 已有手册，点击帮助入口 | 按身份打开现有册，不按标题误认同名用户内容 |
| 手册不存在，用户主动重新添加 | 明确创建一份副本，不恢复或覆盖旧的已删除版本；连续操作不重复创建 |

默认笔记本继续收集日常新建内容。首次打开手册只影响初始阅读位置，不把手册设成用户的默认收件位置，不在每次启动时强制打开，也不增加永久置顶与复杂排序规则。设置中提供一个能稳定找到手册的轻量入口，复用现有导航和添加确认。

内置手册随插件版本维护；用户库中已经加入的副本不静默更新。新版手册获取时也不覆盖旧稿。自动差异合并与版本订阅不在本轮范围。

## 6. 技术落点与试验重点

当前只有默认笔记本自动创建：`src/notes/repository.ts` 的 `ensureNotebooks`、`src/notes/notebooks.ts` 的固定标识。首次接入与同步位于 `src/private-workspace/sync.ts`，归档与同步校验位于 `src/notes/`；正文使用现有 Markdown 和图片组件。初始化不是单纯把六个文件复制进目录。

优先采用：独立的内置内容清单＋现有笔记、资源和修订机制＋明确的首次加入流程。此流程放在仓库身份与远端内容核实之后，避开普通列表读取、打开正文和每轮同步的热路径。

第一轮技术试验必须回答：

1. 稳定的手册/篇目标识，加上现有修订、回收站及删除记录，是否足以保证两台设备、重试和删除后的行为；同一初始内容生成确定结果，不随本机时间产生重复版本。
2. 文件先验证和归档、再形成可读笔记；中断后能识别本轮已完成部分并继续，不生成重复册，也不留下正文指向缺失图片的可见完成状态。
3. 重试前重新核对仓库身份、位置和用户变动；已经被用户修改的部分不覆盖。只恢复可确定为本轮中断的内容。
4. 第一次加入的结果随普通笔记同步；“是否已经提供过”不能只存在某一台设备的浏览器存储中。确认不足时提供手动添加，不猜测空库身份。
5. 初始打开、手动获取与创建操作要避免连续点击重复执行，并有真实完成和失败提示；失败保留可重试状态，不通过重置用户仓库恢复。

优先不改变笔记 schema 和同步格式。若试验发现必须增加同步元数据或升级格式，先更新规划，说明旧版本兼容、迁移和回退影响，经用户确认再扩大范围。不能为了避免格式变更，把可靠性问题藏在本机缓存里。

## 8. 分轮实施与工作量

这是中等规模改动：内容设计占主要体验工作，初始化可靠性是主要工程风险。按三轮推进，不按“加几篇 Markdown”估算成一次简单样式修补；最终工时取决于样章迭代和初始化试验结果。

1. **内容与样章**：核对当前素材和用户修改；整理开发册目录；完成用户册首页、综合示例页和资料页的真实插件样章，验证视觉与操作；补齐六篇和素材清单。交付实际预览及体积初测。
2. **初始化试验与开发**：先验证标识、空库判定、中断重试和跨设备删除，记录取舍；接入一次性加入与手动获取，再归并隔离内容。交付可重复验证的初始化流程及必要测试。
3. **完整验收与交付**：检查整册美观、功能演示、离线与同步、包体及性能；修正后安装到隔离入口，维护实际结果与未覆盖边界。交付体验入口、截图、内容源、包信息和回退方法，未授权发布。

实施前将本规划状态改为已批准；每轮先补充具体试验、修改与验收项，再执行，随结果持续修正。已批准范围内的例行调整不反复请求同一授权；新增功能或格式迁移另行确认。

## 9. 验证与验收

### 内容与视觉

- 先在真实插件中检查首页和样章，不能以独立网页效果代替产品渲染。
- 主界面、独立窗口、会话侧栏均查看；宽屏、常用桌面尺寸、520/360 px 可用窄区，明暗与三个阅读预设抽查；八种布局检查首页基本可用，不重复做无关功能矩阵。
- 首屏有明确主题和视觉吸引力；没有巨图遮住全部导读、重复标题、过密表格、无意义代码、大片空白或硬编码白底文字图造成的明显主题冲突。
- 笔记链接、引用、代码复制、图片切换、附件下载、编辑清单和导出从真实入口走通；所有演示操作与现有能力一致。
- 说明短而准确、场景连贯。每个附件可按格式打开，文件名与大小一致；模拟来源与真实截图可追溯。截图无私人内容。

### 正确性与兼容

涉及初始化、写入与同步，按项目第三档验证：`npm run typecheck`、`npm run build`、`npm test`；生成候选包并核对实际安装及包内容。

覆盖新库、现有空库、远端有内容但本机空、回收站非空、曾彻底删除、重命名/移动/编辑、部分完成重启、资源失败、连续点击、两份独立资料同时接入、版本升级和手动重新添加。确认原内容、修订与附件保持，无重复和静默覆盖。多资料模拟不冒充两台物理设备实测。

真实测试沿用 `.dsh-home/pure-001/` 和 `StarWind97/dsh-community-private-test`。新库/空库的破坏性条件用独立本地测试远端模拟，不清空指定测试私库；真实私库验证普通加入、同步和第二份隔离副本恢复。日常 DSH 资料不动。

### 性能与体积

- 开发前记录同一候选、同一资料与窗口的打开笔记、热切换和首次阅读基线；资料包含前序约 138 篇在用笔记及本轮新增内容，最终数量以实际记录为准。
- 对比普通笔记与手册：首屏文字出现、图片加载完成分别计时；常用操作至少 5 次，报告中位数、最大值、资料规模。首次宿主启动或网络同步样本较少时明确注明。
- 普通阅读新增开销以中位数增加超过 10% 或 50 ms（取较大）作为需要调查的信号；不是通用性能保证。不得引入每次打开的全库检查、重复资源扫描或网络等待。
- 初始化校验和资源复制、网络首次同步、宿主启动分开报告。核对重试和后续启动不重复复制整册。
- 记录压缩包、解包素材、首次同步资料和图片解码/加载表现。超出初始体积预算时给出实际收益和代价，优先处理重复资源和错误加载方式，不机械降低画质。

## 10. 风险、回退与交付物

- **首印象不达标**：样章先行，使用真实插件尺寸调整构图与文案；内容完成不等于视觉验收完成。
- **手册覆盖用户修改或反复复活**：稳定标识、远端核对、删除历史和中断场景共同验证，不按名称或活动笔记数单独判断。
- **多个文件部分写入**：采用可恢复步骤与内容核验，不宣称现有文件库具备跨文件原子事务；失败不扩大到重置仓库。
- **内容过时**：随包清单注明适用产品版本，真实 UI 图控制数量，更新内置源但不静默改用户副本。
- **体积和启动成本**：素材与主脚本分离，按需加载，实测包与首屏；不为手册引入第二套 UI 或字库。
- **回退**：代码用正常回退提交；已加入用户库的手册保留为普通笔记。测试资料仅按本轮清单移动/删除，恢复前再次核对用户编辑，不能用整个旧快照覆盖新资料。

交付物为：两本手册的内容组织与隔离实例；随包用户册和素材来源；首次加入及手动获取实现；持续更新的规划和验证记录；实际安装包与隔离入口。发布、市场更新和公开宣传截图仍需另行授权。
