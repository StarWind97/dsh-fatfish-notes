# 阶段 E：会话相关笔记实施方案

状态：2026-11-10，**待用户确认，尚未开发**。[E0 可行性验证](2026-11-10-e0-conversation-validation.zh.md)已完成。本文只展开[主规划](2026-11-09-product-iteration-roadmap.zh.md)阶段 E；不改变 E → 候选清单回顾 → 按确认补齐或接续 F 的顺序。

后续[材料引用补验](2026-11-10-e0-material-reference-validation.zh.md)已通过：可保存宿主副本，并向输入框加入读取说明，模型能实际读取正文、图片及数据表。建议增加“引用到当前会话”，仍待用户确认后调整下文步骤与验收；本次仅补充证据，尚未开发或扩展已批准范围。原生附件登记继续延期；用户已明确，本项不另行解决会话材料的跨设备同步。

再经[普通附件与交付文件补验](2026-11-10-e0-conversation-files-validation.zh.md)，已确认用户上传文件可按消息取得，AI 正式交付文件可按轮次取得并复制保存；两轮 8 项材料的归属、完整性与重启验证通过。仅被文字提及的路径不自动归档，交付文件保存的是转存时的当前版本。

**下文 E1—E3 仍是第一版待审方案。** 侧栏内继续编辑、材料引用、普通文件转存和工作区默认笔记本尚未统一纳入步骤、影响面及验收；正式开发前应合并修订，不能把补验通过视为功能已实现或整个 E 已获开发授权。

## 已确认的笔记本约束（未实施）

- 不设置“为当前会话新建”入口或会话专用笔记本映射；保留“为当前工作区新建”。未分组会话可新建普通笔记本，不要求映射。
- 每次转存均可选择任意已有有效笔记本。为当前工作区建立对应笔记本后，或已有对应关系时，预选该本，仍可改选。
- 工作区本仍是私人库内的普通笔记本；所有普通笔记继续允许修改归属，不因工作区默认或来源会话而锁定。
- 建议一次转存改选只作用于本次，不静默改写工作区对应关系；此细节待统一方案确认。

## 目标与取舍（第一版，待统一修订）

让用户在 DSH 会话旁边找到、阅读和管理相关笔记，需要深入编辑时打开现有独立窗口，继续保留会话工作位置。

本阶段实施：宿主右侧栏中的「会话笔记」、当前会话来源笔记、手动关联/解除、查找已有笔记、只读预览、在完整笔记窗口打开。

本阶段不实施：直接附加到输入框、自动发送、AI 分析/重写、会话本身的跨设备同步、复制粘贴代替附件、下载后手工附加的新入口、全库语义推荐。附件接口不完备，保留明确待办；侧栏不会声称关联内容已经交给模型。

| 选择 | 取舍 |
| --- | --- |
| **使用宿主公开右栏 tab（推荐）** | 与文件等工具共存，复用宿主的展开、折叠、宽度和窄屏行为；不替换整个右栏。 |
| 自建覆盖层侧栏 | 需要重复维护布局、焦点和第三方共存，不采用。 |
| **手动关系存为笔记可选元数据（推荐）** | 复用不可变修订、校验、按篇编辑保护和私库同步；关系变化会产生笔记修订及修改时间，能出现在历史中。 |
| 独立关系数据库或同步模块 | 可以避免关系修改影响笔记修订，但增加事务、清理和同步规则，当前收益不足。仅存浏览器也不采用，避免换窗口或换设备后丢失手动关系。 |

## 用户操作

1. 已开始会话右上方增加轻量笔记图标，悬停显示「会话笔记」；宿主右栏工具页也提供肥鱼笔记入口，覆盖有身份的空白会话。没有有效会话时不执行关联。
2. 打开后显示两组：「从本会话保存」「关联的笔记」。列表只显示标题、摘要和笔记本，避免同时搬入完整笔记库的三栏管理界面。
3. 「关联笔记」打开侧栏内的查找视图，复用现有标题/标签/正文搜索，可选择笔记本。选择一篇完成关联；已有关系不重复添加。普通来源笔记已自动出现，无需再次手动关联。
4. 点列表项在侧栏阅读，提供返回列表、在独立窗口打开；完整编辑仍在笔记界面进行。只读预览复用 Markdown、图片、附件下载和文章内链能力，不增加第二套编辑器。
5. 手动关联项可「解除关联」，提供撤销；只移除关系，不删除笔记。来源组不可用该动作篡改原始选材。
6. 切换会话后只显示目标会话的相关笔记，迟到的请求不能覆盖新会话。首次打开、列表为空、尚未初始化、网络暂不可用分别给出简短清楚的提示。
7. 首次使用侧栏说明「关联便于查找，不会自动发送给 AI」。不展示底层 ID、Git 路径等技术细节。浅色/深色跟随宿主；标题截断时有完整提示。

宽屏沿用宿主的并排面板；窄屏可能由宿主转为覆盖展示，不承诺任何宽度都能并排。已有独立笔记窗口仍是窄屏下并行工作的选择。侧栏不自动展开或抢占用户正在使用的工具页。

## 数据与并发规则

- 来源关系从当前有效笔记的 `sourceId` 指向原始 `sessionId` 推导，不修改来源文件。关联查询排除模板和回收站；恢复笔记后关系可重新显示。
- 手动关系拟增加可选 `relatedSessionIds` 集合，缺省为空，去重、限长和校验；只存会话身份，不复制对话、标题、路径或账号凭据。按当前绑定私库隔离，不以标题/工作目录猜测会话。
- 新旧格式的读取、版本识别、Markdown 元数据和同步校验一并覆盖。没有关系的旧笔记不批量重写。旧包遇到不支持的字段/格式应停止同步，不允许忽略字段后写回；同库实例使用支持新字段的版本。
- 关联/解除使用当前版本检查与现有写入队列、窗口占用保护；有未完成编辑时先按现有保存流程完成，另一窗口正在编辑时提示稍后操作，不绕过锁或用旧正文覆盖新正文。
- 普通正文保存与历史正文恢复保留当前手动关系；历史预览展示当时记录。复制、新建模板及从模板新建默认不继承手动关系，普通副本原有的来源保留规则不变。
- 回收站保留关系但侧栏不显示；彻底删除按现有流程清理该笔记及独有文件，无须另一套关系垃圾回收。
- 多端偶发笔记冲突继续沿用保留两份的规则，不新增关系专用合并系统。另一设备没有该会话时笔记仍可阅读，不尝试自动重建会话或转到同名会话。
- 导出给其他软件时不携带宿主会话编号；导入文件不据文件中的任意编号建立会话关系。私库内部元数据与便携导出分开处理。

## 顺序与交付

| 步骤 | 工作内容 | 完成条件 |
| --- | --- | --- |
| E0（完成） | 公共接口、隔离侧栏/上传探针、来源关系核查 | 见验证记录；直接附加受限已明确。 |
| E1 | 公开 tab 注册与入口；服务端来源索引；相关列表、搜索与只读预览；独立窗口打开指定笔记 | 两个会话切换不串内容；宿主工具页共存；真实笔记图文可读；不影响会话输入。 |
| E2 | 手动关系字段与操作；保存、恢复、复制、删除、导入导出与私库同步规则 | 关联/解除/撤销、重启、两份隔离资料同步和写入保护通过；既有正文及原始素材不受破坏。 |
| E3 | 整体交互与性能验收，使用说明、截图和统一体验入口 | 用户集中体验 E；交付时主动回顾候选清单，建议补齐/保留/移除并等待选取。 |

批准后按 E1 → E2 → E3 连续推进，日常技术选择由 Agent 处理；若宿主接口或数据方案出现实质变化，再提出取舍。完成后集中体验，不默认每小步发版。直接附加不作为本次 E 完成的阻塞条件，正式发布另行确认。

工作量为中等，预计 3 个实施批次；E2 存储与同步验证占主要工作量，E1 复用已有阅读/搜索组件。不是只增加一个按钮，也无需重做笔记存储体系。

## 影响面

- `src/client/index.tsx`：公共侧栏类型、正文和入口注册；新增侧栏组件与状态管理。复用现有阅读、搜索、窗口打开及刷新能力，相关样式限制在插件自身。
- `src/contracts/notes.ts`、`src/notes/validation.ts`、`revisions.ts`、`repository.ts`、`markdown.ts`、`sync.ts` 及必要的导入导出适配：新关系字段、查询和写入语义；检查复制、恢复、冲突等是否完整保留或清空关系。
- `src/host/routes.ts` 与客户端 API：增加按会话查相关笔记、关联/解除操作；继续使用 loopback、Origin、仓库身份和按篇编辑保护。独立窗口打开指定笔记已有接口，直接复用。
- `package.json` / lock：增加实际使用的同版本官方 `dsh-client-ui-sidebar-right` 类型依赖和客户端注入声明；不引入独立 UI 框架、数据库或模型 SDK。不为本次延期的直接附加增加运行依赖。
- 测试、产品设计、使用说明、开发入口和验证记录同步更新。产品可见的关联说明以实际实现为准。

## 性能与验证

E0 只有接口可行性和单次来源映射测量，不能充当正式性能验收。E1 开始先测 0.8.0 受影响的现有操作基线。

- 当前测试库为 83 个对象、282 个笔记修订；另用隔离生成资料覆盖约 1000 篇、多个会话关联。大资料测试不推送真实私库。
- 列表只取所需摘要，不预读全部正文/图片，不在客户端逐篇查询来源；来源按哈希复用，索引按仓库代次和内容变化失效，换库及失败丢弃。隐藏侧栏停止其业务刷新，不重复触发 Git 同步。
- 本机读取不等待网络；会话切换取消过期请求。依靠已有本机变化机制刷新新增转存、关联和独立窗口保存后的内容，避免每次轮询全历史扫描。
- 初步目标：当前规模首次相关列表显示约 1 秒内，热切换/普通预览中位数 300 ms 内、最大值 500 ms 内；同机同资料、同窗口、实际显示完成为口径，常用操作各至少 5 次。1000 篇的结果单列，不把小样本承诺为普遍速度。
- 第三档验证：类型检查、构建、全量回归；覆盖关联幂等、来源与使用关系分离、恢复/副本/模板、回收站、写入冲突、格式校验、同步/断网恢复、导出不泄露会话编号。
- 真实隔离 Desktop 与 Web：两会话、浅深色、宽窄屏、同篇编辑占用、另窗保存刷新、列表跳转和宿主原有工具共存。使用指定私有测试仓库验证关系推拉及重启，不称为两台物理设备验收。
- E3 产出截图和实际耗时表；保持真实、模拟、未覆盖边界分开。没有直接附加时不做误导性的「发送给 AI」按钮。正式发版前另打包验证安装。

## 风险与回退

- 宿主升级可能改变右栏接口：按当前 0.2.2-rc.1 固定验证；侧栏入口失效时完整笔记界面仍可用，不替换宿主组件补洞。
- 关系写入是笔记元数据修改，会产生新修订并影响修改时间；先复用现有语义，避免增加另一套时间和同步模型。如果用户不接受这一取舍，开发前改议独立关系存储。
- 存储字段变化前备份隔离资料，保护既有笔记。E1 可回退注册与界面改动；E2 写入新字段后不能只装旧包声称完成回退，需要配套恢复升级前隔离备份，或以向前修复保留之后新增内容。不得为回退重写远端 Git 历史。
- 直接附加缺口保留在主规划备忘：等宿主公开安全文件接收/登记接口后重新验证 Markdown、图片、取消、切换和模型可读性，再讨论是否纳入后续版本。

本方案需用户明确确认后进入 E1—E3；E0 完成不代表手动关联、同步和正式侧栏已经实现。
