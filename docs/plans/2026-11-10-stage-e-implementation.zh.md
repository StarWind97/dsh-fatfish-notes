# 阶段 E：会话侧栏、材料转存与引用实施方案

状态：2026-11-11，**用户已明确批准整版方案，E1—E3 已完成开发和隔离验收，待用户集中体验。** 正式版仍为 0.8.0；实际验证、截图和操作入口见[交付记录](2026-11-11-stage-e-results.zh.md)。本文保留已批准的实施与验收依据，正式发布另行确认。

本文展开[主规划](2026-11-09-product-iteration-roadmap.zh.md)的 E 阶段，替代此前仅含只读侧栏的第一版方案。顺序保持：E → 候选清单回顾 → 按确认补齐或接续 F。A—D 已发布，不重新实施。Agent 负责推进、验收材料和提醒，用户无需逐项维护节点；正式发布另行确认。

## 目标和范围

让用户留在 DSH 会话中，就能查阅、修改相关笔记，把会话内容和文件存入笔记，再把选中的笔记材料交回当前会话使用。

本阶段拟交付：

1. 宿主右侧「会话笔记」：相关列表、查找、阅读和原地编辑，保留完整独立窗口入口。
2. 会话来源与手动关联；工作区对应的默认笔记本。
3. 现有「保存到笔记」「导出」和侧栏入口共用图片、普通附件选择能力。
4. 「引用到当前会话」：把所选笔记材料保存为宿主副本，向输入框加入文件引用及简短读取说明，由用户检查并发送。
5. 常见规模下的进度、取消和响应保障；统一审核现有体积限制，避免入口规则不一致。

不纳入：AI 整理正文或分析输出、自动发送消息、全库语义推荐、独立聊天系统、原生输入框附件登记、会话跨设备同步、工作区历史备份、音视频播放与复杂附件预览、Git LFS 或另一套云文件存储。百万字文章、单个超大文件的专项优化后置；由普通文件组成、合计超过旧 200 MiB 上限的批次仍应可处理，不据总量判作不支持。

## 已确认的取舍

- 用户已确认只保留“为当前工作区新建”，不设“为当前会话新建”及会话专用笔记本映射。
- 未分组会话可以新建普通笔记本，不要求对应关系；每次转存都可选择任意已有有效笔记本。
- 工作区已有对应本，或新建并建立对应后，默认选中该本，仍可改选。所有普通笔记均可再改变归属，原始会话来源不随移动而改变。
- 用户要求兼顾已有保存和导出入口，先参考同类产品、补充少量测试，优先做好常见情况；较大处理显示明确进度、允许取消，尽量允许继续其他工作，不能让整个界面一直卡死。
- 容量建议经用户明确接受，唯单次 200 MiB 封顶被指出缺少依据；修订为不设这个固定批次总量上限，进度、取消及其他操作可用是完成条件。接受容量规则不等于正式 E 功能已交付。
- 导入重计算明确使用 Web Worker 后台工作线程，不能仅加进度条或在界面线程中延迟启动同样的同步工作。异步文件读写与多线程分别设计、分别验证。
- 下文其余整合后的实施建议随整版确认：一次改选只影响本次保存，不自动改写工作区默认；工作区映射留本机；附件默认勾选和导出打包方式。这些取舍已随整版获准实施；实际结果见[交付记录](2026-11-11-stage-e-results.zh.md)。

## 用户操作

### 会话侧栏与继续编辑

- 复用宿主公开右栏 tab 和会话工具入口，不替换其他工具页、不默认抢占侧栏。布局和主题跟随宿主；窄屏空间不足时，可打开现有独立笔记窗口。
- 显示「从本会话保存」「关联的笔记」，提供查找、关联、转存当前会话和打开完整窗口。工作区默认本只是保存位置，不将其中全部笔记自动关联到本会话。
- 点击笔记在侧栏阅读；点击编辑后原地修改标题、摘要、标签、笔记本与正文，复用现有 Markdown 编辑器和自动保存，不维护第二套编辑器；工具栏按宽度收纳。
- 转存成功后，**本机保存完成就刷新侧栏并选中新笔记**，可继续编辑；不等待 GitHub 同步或可选标题/摘要/标签建议完成。仅在该会话侧栏仍打开时选中，不展开已关闭的侧栏，不覆盖已切换的另一会话。
- 标题/摘要/标签建议继续是转存时可选项，沿用现有候选采用与版本检查：用户已修改笔记时不自动覆盖；建议失败或取消不影响已经保存的原文，也不增加新的正文 AI 整理。模型处理预算独立于附件保存上限，不因容量放宽自动向模型发送更多文件。
- 会话切换、关闭侧栏、打开完整窗口沿用自动保存；所有界面共用按篇编辑保护。同篇在另一窗口编辑时可阅读并提示占用，不同时写入。编辑只改笔记正文和信息，不改原始素材。
- 一篇笔记可手动关联多个会话；解除只移除关系，提供撤销，不删除笔记。来源组保持原始来源事实。关联便于查找，不代表模型已读取笔记。

### 选择笔记本

- 转存始终可选择任意有效笔记本；优先预选工作区对应本，否则用私人库默认本。
- 有工作区时提供“为当前工作区新建”，建议名称取工作区名称并允许修改；也可明确指定一本已有本作为该工作区默认。
- 未分组会话提供普通“新建笔记本”，不建立会话专用映射。
- 偶尔改选只影响此次转存，更改工作区默认是明确操作；对应本被移除时退回私人库默认本，不阻止保存、不自动新建替代本。
- 工作区本仍在同一私人库内，不额外建立 GitHub 仓库，也不在工作区里另建笔记存储目录。

### 保存和导出时选择图片与附件

- 先选当前问答、多轮或整个会话，再展示范围内材料。会话下方已有保存、导出按钮与侧栏入口共用选择组件和服务端规则。
- 默认勾选范围内可用图片和文件，允许逐项取消、全选/全不选，显示名称、类型、大小和合计。无附件时隐藏该区域，不增加必经步骤；超过提醒阈值时集中提醒一次。
- 用户上传文件跟随所属消息；AI 正式交付文件显示为“本轮交付文件”，按消息细选时仍可单选，不猜属于哪段回答。仅提及的路径和未交付的工作区文件不自动归档，不扫描工作区。
- 保存时复制所选材料；符合预览规则的图片显示在正文中，超出规则的图片经提示作为普通附件保留原图，普通文件提供下载。取消选中的材料不偷偷归档，生成内容标明“未包含”，避免留下看似可用的本机链接。失败项可取消或明确跳过后继续，不假报完整保存。
- 原始选材保存所选消息的原文以及文件选择、归档结果；“未包含”等提示属于展示和归档状态，不让日常正文编辑改写原始素材。源文件读取期间变化或消失时提示重新读取/跳过，不保存拼接的半新半旧文件。
- 用通俗说明提示文件版本：“如果 AI 后来修改过这个文件，这次保存的是修改后的内容。保存到笔记后，原文件再变也不会影响这份副本。”不为此建设工作区文件历史系统。
- Markdown 仅文字可导出单个文件；包含所选图片或附件时打包，正文用相对路径。PDF/长图/多图展示文字和所选图片，普通附件只显示名称；要带走普通附件时，把生成文件和附件一起放入 ZIP，不声称音视频已嵌入页面。
- 笔记内导出复用附件选择和格式说明；选择只影响此次导出，不修改笔记、不删除库内材料。整库导出的逐文件精细选择不在本批扩展。

### 引用到当前会话

- 首次范围为单篇，可选择带入的图片和普通附件；先完成自动保存，再准备这个已保存版本的副本。
- 调用宿主附件服务保存副本，改写材料内部引用，通过公开输入接口加入简短读取说明；保留已有文字和附件，支持撤销，不自动发送。
- 只针对有效会话和可用输入框；准备期间输入或会话变化时停止插入、提示重试，不覆盖新草稿。只处理用户选中的笔记和合法附件，不扫描其他私人资料。完整窗口通过明确的会话上下文发起引用；独立窗口不猜测宿主“当前会话”，没有上下文时引导回会话侧栏引用。
- 文案用“引用到当前会话”“已加入读取说明”，不称“已附加到附件栏”。关联和引用分开，不因打开侧栏就把内容交给模型。
- 副本由 DSH 管理，不在工作区建立中转目录；修改笔记、搬迁笔记库不改变已引用副本。首版核验本机 Windows，不承诺 WSL/远程路径通用；不支持的执行环境明确提示。
- 不自行清理宿主附件目录，不为此增加跨设备同步。原生附件栏能力按主规划[接口复查备忘](2026-11-09-product-iteration-roadmap.zh.md#宿主接口开放后补齐直接附加)在宿主升级、E 后回顾及 F 规划时核查并提醒。

## 数据与实现取舍

| 项目 | 推荐做法及原因 |
| --- | --- |
| 侧栏与编辑 | 公开 tab + 现有阅读/编辑组件，避免覆盖宿主或维护第二套编辑器。 |
| 来源与手动关联 | 来源继续由 sourceId 推导；手动关系作为可选笔记元数据，沿用修订和同步。关联会更新笔记修改时间，不另建关系数据库。 |
| 工作区默认本 | 用宿主公共工作区身份，映射按私人库身份隔离，存插件本机配置；不按名称/路径猜关系，不要求不同设备有同一 DSH 工作区。 |
| 文件选材 | 服务端冻结范围，客户端只提交选中项身份；服务端核对消息/轮次归属、路径、体积和读取结果，不开放任意本机路径读取。 |
| 文件保存 | 复用图片/普通附件存储、共享引用和彻底删除规则；原始素材与可编辑正文分开。引用到会话的副本用宿主公共附件服务。 |

- 查询排除模板和回收站，恢复后可显示；普通编辑、换本和历史正文恢复保留当前关联。复制及从模板新建不继承手动关联，已有来源保留规则不变。
- 便携导出不携带宿主会话编号或本机工作区映射；导入不按任意编号建关系。另一设备没有原会话时仍可阅读笔记，不重建会话或跳转同名会话。
- 关系及来源附件结构变化，以及旧包不能读取的容量变化，须一并更新格式识别、读取/保存/同步校验。新版本读取 0.8.0 资料；写入新格式前有版本标记，旧包不得忽略新字段后写回，同库实例使用匹配版本，不预建复杂兼容框架。
- 写入复用版本检查、队列和编辑占用。偶发多端冲突继续保留两篇供用户取舍，不增加专用合并系统。
- 正文、原始素材及保留的历史修订共同参与图片/附件引用检查；修改正文或取消未完成任务不能误清仍被来源、其他笔记或历史引用的文件。
- 取消停止后续工作；已导入笔记保留并报告，正在提交的单篇按原子保存完成或失败，不假装取消会撤销全部已完成结果。

## 体积与性能：只围绕常见使用

用户明确本插件以会话材料、日常笔记为主；**本轮限制评估的重点是图片与普通文件的单个大小、合计大小和数量，文字只保留基本检查，不作为容量测试主线。** 不将百万字文章、几百兆至 GB 文件作为常见场景。先参考竞品公开说明，再做少量针对性测试；不开展代表所有电脑的硬件评测，不为极端规模重建架构。

| 当前 0.8.0 规则（尚未修改） | 衡量内容 |
| --- | --- |
| Markdown 单篇 10 MiB | 文件本身的字节数，含文字、属性、链接地址，不含另存的图片/文件。正文保存也有 UTF-8 字节上限。 |
| 图片单张 5 MiB、合计 20 MiB | 图片文件的字节，不等同于像素数或显示时的内存开销。 |
| 普通附件超过 10 MiB 确认、超过 50 MiB 拒绝，每篇合计 200 MiB | PDF、音频、视频等下载型文件，不要求编辑器解析其中内容。 |
| 文件夹/ZIP 每批 200 MiB | 纳入本批的文件总量；ZIP 还检查解压后的大小，不能只看压缩包有多小。 |
| 单篇最多 128 张图片、128 个普通附件 | 两类分别计数，是当前实现的保护值，不是已测定的性能极限。 |
| 导入批次最多 10,000 项、5,000 篇笔记 | ZIP 项计数还会涉及目录项；文件夹扫描按纳入项计数。用于保护批量处理，不作为常见验收规模。 |
| 笔记数据目录累计 512 MiB；库内最多 5,000 篇 | 512 MiB 检查覆盖 `notes/` 下正文、修订、素材、图片和附件等实际文件，不含仓库的 `.git/`；远端快照读取也受累计限制。5,000 篇按保留修订的不同笔记 ID 计数，含回收站和模板，不是每个笔记本各有 5,000 篇。 |

这些当前数值不是已测定的流畅运行边界。以下为讨论后采用的 E 容量规则，尚未改入 0.8.0：

| 项目 | E 实施规则 |
| --- | --- |
| 单个文件保存 | 超过 50 MiB 集中提醒，超过 100 MiB 拒绝；图片原件作为普通附件时也遵守此规则。 |
| 图片在正文中显示 | 暂定同时不超过 20 MiB、3200 万像素；任一超出时提示并允许作为普通附件保存原图，不自动压缩。现有不支持的图片格式仍可按普通附件保存。此为预览保护策略，非硬件性能结论。 |
| 单篇合计体积 | 取消图片 20 MiB、普通附件 200 MiB 的累计硬上限；图片按需加载，附件逐个处理。 |
| 单篇数量 | 保留最多 128 张图片及 128 个普通附件，分别计数。 |
| 单次导入/转存合计体积 | 撤回固定 200 MiB 封顶，不要求用户仅因总量超出而手工拆批；插件内部逐文件/分块处理并限制并发。 |
| 导入批次数量 | 保留最多 10,000 项、5,000 篇；提前显示有效材料数量、跳过项及原因。 |
| 整库体积 | 改造集中读取后取消 512 MiB 硬封顶；约 1 GiB 温和提醒、约 5 GiB 明显提醒，不因提醒值停止保存；当前资料与 Git 历史占用区分显示。 |
| 整库数量及历史 | 暂保留 5,000 篇及合计 100,000 个修订保护值；提前提示，不自动删除历史，达到限额仍可阅读、导出和清理。 |
| 文字 | 保持现有正文/Markdown 10 MiB、原始快照 20 MiB 等基本校验，不扩大长文本优化。 |

**取消批次/整库体积封顶必须伴随处理方式调整，不只删除常量。** 0.8.0 的 ZIP 先整包读取，再用 `unzipSync` 在界面线程展开并保留文件内容；文件夹附件虽可按需读取，前期扫描仍受同一总量限制。200 MiB 是保守实现保护，不是经过测量的电脑性能界限。E 开发版已将解压/解析及编码放到 Worker，以临时分块存储承接文件；正式入口的进度、取消和内存测量见交付记录。

E2 统一处理上传、图片显示、保存、导入、同步和整库导出：限制同时保留的文件数据，处理完及时释放；必要时用插件控制目录内的临时文件承接。导入解压及较重解析/转换明确放到 Web Worker，不能把整个包搬进 Worker 后继续无限堆积。具体分工与操作生命周期见下节。

进度可收起，用户可继续 DSH 会话及操作其他笔记；仅对正在写入的对象保留必要保护，不全局锁住界面。扫描总量未知时显示已发现/已处理项，已知后显示文件数量及字节进度；本机导入完成与云端同步分别提示。保留单文件/数量、路径、压缩包完整性及实际资源不足等必要检查，出现问题说明具体原因，不改用另一个无依据的固定总量数字。

整库累计会随着正常资料及历史增长，不能把超过 512 MiB 视为极端使用。取消整体硬限须同步改造文件集中读取，不能把 512 改大便宣称完成；1/5 GiB 仅为提醒策略，不是不限规模流畅的承诺。涉及内存处理和同步的调整是 E2 的主要工作之一。

参考及小测见[补充记录](2026-11-10-e-import-size-reference.zh.md)。图片/文件四种场景各测 5 次：1/8 MiB 文件前端准备、8 个约 1.9 MiB JPEG 解码、50 篇加 16 项媒体的 ZIP 解压扫描。常见环节中位数约 23–173 ms，仍有约 0.18 秒的同步任务；结果支持先处理必要的分批和让出执行时间，未证明完整导入/保存/同步或较大上限附近流畅。已做的 1 万/5 万字符转换只作为附带记录，不再扩大文字测试或进行极端压力测试。

正式验收要求：

- 当前隔离小库基础上验证相关列表、切换、普通图文和几十项材料的小批次；既有长文只做编辑功能抽查，不再将百万字或 1000 篇合成库压测列为本批强制门槛。
- 另外使用少量普通文件组成、合计略超旧 200 MiB 的目录/ZIP 验证新规则；检查实际完成、内容完整、处理中取消及切换会话的响应，并核对内存没有随整个包持续堆积。为取消整库 512 MiB 封顶做一次针对性跨旧边界验证，不扩展为 GB 级单文件压测。
- 列表只取摘要，不预读全库正文/图片、不逐篇扫描全部会话；索引随内容变化失效。隐藏侧栏停止刷新，不重复触发 Git 同步，本机阅读不等待网络。
- 常用操作目标约 0.2 秒内有可见反馈；热切换/普通阅读中位数约 300 ms 内、最大约 500 ms 内，首次相关列表约 1 秒内。实际内容显示与“已开始处理”提示分别测量，不用转圈冒充加载完成。
- 较大处理显示当前文件、已完成数量/总量、提供取消；重计算放工作线程，异步读写限制并发。持续数秒可以解释，长时间不能点击、滚动或取消不合格；未知总量时报告已完成项，不编造百分比。
- 不为每个小文件传输建立任务中心或永久任务日志；本轮仅维护运行中的批次状态及必要恢复信息，不预建通用作业平台。

## 多线程、文件处理与操作生命周期

### 明确的线程分工

| 执行位置 | 负责的工作 | 边界 |
| --- | --- | --- |
| 界面主线程 | 操作响应、进度与列表的轻量更新、向宿主发起公开接口调用 | 不执行整包 ZIP 解压或批量 Markdown 解析/转换；进度更新节流，长列表分页展示。 |
| Web Worker 后台工作线程 | ZIP 分块解压、较重的 Markdown 解析/链接转换、文件编码等导入计算 | 使用现有依赖单独构建 Worker 入口，数据按块交接并及时释放；不依赖 DOM 或宿主 UI 注入对象。 |
| Host 异步文件服务 | 有限并发的分块接收、读写、完整性校验、临时文件和正式保存；宿主公开附件/工作区接口仍在合法调用环境内使用 | 异步读写不是多线程；避免把大文件完整编码为一个巨大的 JSON 请求，避免整库快照常驻内存。 |
| Host 工作线程（需要服务端重计算时） | 必须在服务端执行的整包压缩等 CPU 密集工作 | 使用 Node 工作线程，普通磁盘/网络读写不为“多线程”额外创建线程；不能把阻塞从页面转移到 Host 事件循环。 |

选择 Web Worker，而非“主线程延迟执行 + 转圈”：后者仍会阻塞点击和取消。异步解压整个包虽可避免主线程计算，仍可能堆积整包内容，因此还必须配合分块、有限并发和临时文件。界面线程仍承担少量必要更新，不承诺零 CPU 占用，也不以 `async` 关键字证明多线程已经生效。

Worker 资源随安装包构建，通过插件受支持的资源入口加载；嵌入 DSH、Web 与独立窗口分别核验。E2a 先验证线程确已启动、能中断、无需放宽宿主安全设置，再接入业务。若加载不通，修正受支持的加载方式；不能悄悄回退为主线程执行大任务并宣布达标。会实质改变方案时再说明。

同步与导出取消整库封顶时，仍冻结笔记修订和文件身份，分批读取并核对完整性；不把“分块”做成混合不同版本的快照。大文件读取/准备不长期占住整库写入队列，正式提交保留短时版本检查和排他保护。导出取消后不交付看似完整的残缺包；现有 PDF/图片的画布、页数及编码保护按具体渲染需要保留，相关转换预算与新图片规则一起核对，不把渲染限制反过来变成笔记保存限制。

### 运行、取消与继续其他工作

- 默认同一笔记库一次运行一个批量导入/转存任务，控制工作线程和文件并发；不会禁止阅读或编辑其他笔记。进度状态独立于弹窗/侧栏组件，收起进度或切换宿主页面不丢任务。
- 批次固定仓库身份、来源会话截止点、目标笔记本及选择范围；切换到另一会话不改变它们、不把结果插入另一会话。切库或搬迁资料前，要求先完成或取消正在使用该库的批次；不把这些低频维护操作与普通会话切换混为一谈。
- 取消信号覆盖扫描、分块读取、解压和传输，必要时终止 Worker；停止后续准备，清理本任务未采用的临时材料。正在正式提交的单篇完成或失败后报告实际结果，已完成笔记保留；共享或已提交的附件不随取消删除。已保存到 DSH 的引用副本沿用宿主管理，不直接清理其内部目录。
- 刷新/关闭发起任务的运行窗口、关闭 DSH 或服务断开时，停止后续工作并保留已完成笔记，临时状态按任务归属清理。收起面板不等于关闭运行窗口；本阶段不承诺退出 DSH 后继续运行，也不新增跨重启的大批次断点续传系统。现有会话转存的重试身份保护继续保留，导入同一运行批次重试不重复已完成项。
- 不同任务分别反馈“本机已保存”“正在同步”“已加入读取说明”；显示当前文件、成功/失败/跳过数量，失败可从剩余材料继续。数量未知时先显示已处理量，不编造剩余时间和百分比。
- 单文件、数量、路径、压缩包完整性和资源不足检查保留；超过大小的文件在开始复制前提示。数量限额检查在新增写入前进行，已有内容的阅读、导出和清理不因达到配额一同失效；不自动裁剪正文、丢图片或清理历史。

## 实施顺序与交付

| 步骤 | 工作内容 | 完成条件 |
| --- | --- | --- |
| E0（接口已补验，本轮整合规划及小测） | 后续决定、竞品限制参考、常见规模小测 | 区分事实、建议、未覆盖；整版审核后再开发。 |
| E1：侧栏与组织 | E1a 复用界面、来源查询；E1b 关联契约/格式识别及编辑保护；E1c 工作区默认本和转存后刷新 | 先接现有转存事件，普通文件选材待 E2；本机保存后即显示；不串会话；任何本可选、归属可改；映射和关联重启恢复。 |
| E2a：线程与传输基础 | 先在真实宿主验证 Worker 资源加载、运行及中断；再完成分块文件传输和运行状态管理 | 确认重计算离开界面线程，收起面板仍运行，取消与身份检查有效；不先开放新容量。 |
| E2b：容量与存储联动 | 图片预览/附件回退、限值统一、按需加载、同步与整库导出分批处理、格式升级保护 | 跨 200/512 MiB 旧边界；实际内容完整；允许其他操作；新容量与旧包隔离；满足后开放规则。 |
| E2c：会话材料流转 | 共用选材 UI、上传/交付文件转存、各格式导出、单篇引用，接入 E1 侧栏 | 文件原样保存、导出说明一致；副本不随原件改变；不覆盖输入、不自动发送；失败/取消明确。 |
| E3：集中验收 | 回归、真实宿主、私库同步、性能；文档/截图/体验入口 | 用户集中体验；Agent 主动回顾候选清单和原生附件接口；发布另行确认。 |

E1 → E2a → E2b → E2c → E3 是同一 E 阶段的内部顺序，不是五次发布或五次申请授权。E0 现有证据按需复用；正式开发前测量受影响路径基线，代码改变后再测。E2b 需要的传输与内存基础先由 E2a 提供，E2c 的完整文件保存不提前承诺已在 E1 交付。

工作量中等偏大：E1 主要是组件复用与数据关联；E2 是主体，涉及 Worker 构建、流式处理、存储/同步和文件选材，不是修改几个常量；E3 以集成验证和体验材料为主。整版获批后连续完成，不要求用户逐项提醒，实质范围变化再讨论。

## 影响面、验证与回退

- 客户端：入口、新侧栏/关联视图、编辑控制器、NoteCapture、CaptureSelection、ConversationExport、NoteExport、LibraryTransfer、导入/附件 Worker 和批次状态；共用组件和限定样式。
- 数据：contracts/notes、notes 下采集/来源/校验/修订/导入导出/删除/同步；工作区映射放 private-workspace 相关本机配置，不写用户工作区。
- Host：note-conversation、routes、附件准备/引用服务、git 后端分批读取和必要压缩工作线程；受控临时文件不进入私库同步。保留 loopback、Origin、仓库身份、文件归属/完整性和编辑保护。
- 构建与安装：scripts/build.ts、客户端 Worker 资源入口及包内容检查；Worker 只打包实际所需解析/压缩代码，不加载宿主 UI 包。实际安装中核对资源 URL、线程生命周期和清理。
- 依赖：只引入实际使用、与已验证 DSH 对齐的公共侧栏、输入、附件及工作区声明，核对注入版本；不增加 UI 框架、数据库或模型 SDK。
- 第三档：类型检查、构建、全量回归；覆盖格式识别、关联幂等、来源与使用关系分离、恢复/复制/模板、共享文件与删除、离线保存、私库推拉及导出边界。
- 真实隔离 Desktop/Web 验证正式入口，Windows 测本机文件引用；覆盖主题、宽窄侧栏、两会话、主界面/独立窗口/侧栏同篇编辑、已有输入/附件、中文输入、撤销/失败/取消。指定私库及同机两份资料验证同步，不冒充两台设备或 macOS 验收。
- 既有模型读取证据能复用时不反复消耗额度；正式链路变化后做少量合成材料验证，说明图文/文件覆盖，接口可读不代表模型理解任意格式。
- 本轮规划/小测不改正式包。开发前备份隔离资料；回退采用回退提交，格式变化配套恢复升级前备份或向前修复，不只降级旧包写新数据、不重写远端历史。
- 交付截图、实际耗时、指引和未覆盖边界，关闭自建测试进程，保留可重开的隔离入口；正式发布前再打包验证安装。
