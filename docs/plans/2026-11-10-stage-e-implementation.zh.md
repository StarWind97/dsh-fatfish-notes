# 阶段 E：会话侧栏、材料转存与引用实施方案

状态：2026-11-10，**讨论整合版已落盘，正式功能尚未开发，整版实施待用户确认。** 本轮授权整理规划、参考竞品并按需做小范围测试，不等于批准修改正式功能。当前产品仍为 0.8.0。

本文展开[主规划](2026-11-09-product-iteration-roadmap.zh.md)的 E 阶段，替代此前仅含只读侧栏的第一版方案。顺序保持：E → 候选清单回顾 → 按确认补齐或接续 F。A—D 已发布，不重新实施。Agent 负责推进、验收材料和提醒，用户无需逐项维护节点；正式发布另行确认。

## 目标和范围

让用户留在 DSH 会话中，就能查阅、修改相关笔记，把会话内容和文件存入笔记，再把选中的笔记材料交回当前会话使用。

本阶段拟交付：

1. 宿主右侧「会话笔记」：相关列表、查找、阅读和原地编辑，保留完整独立窗口入口。
2. 会话来源与手动关联；工作区对应的默认笔记本。
3. 现有「保存到笔记」「导出」和侧栏入口共用图片、普通附件选择能力。
4. 「引用到当前会话」：把所选笔记材料保存为宿主副本，向输入框加入文件引用及简短读取说明，由用户检查并发送。
5. 常见规模下的进度、取消和响应保障；统一审核现有体积限制，避免入口规则不一致。

不纳入：AI 整理正文或分析输出、自动发送消息、全库语义推荐、独立聊天系统、原生输入框附件登记、会话跨设备同步、工作区历史备份、音视频播放与复杂附件预览、Git LFS 或另一套云文件存储。百万字文章、几百兆至 GB 级材料的专项优化后置，不作为 E 完成条件。

## 已确认的取舍与待审细节

- 用户已确认只保留“为当前工作区新建”，不设“为当前会话新建”及会话专用笔记本映射。
- 未分组会话可以新建普通笔记本，不要求对应关系；每次转存都可选择任意已有有效笔记本。
- 工作区已有对应本，或新建并建立对应后，默认选中该本，仍可改选。所有普通笔记均可再改变归属，原始会话来源不随移动而改变。
- 用户要求兼顾已有保存和导出入口，先参考同类产品、补充少量测试，优先做好常见情况；较大处理显示明确进度、允许取消，尽量允许继续其他工作，不能让整个界面一直卡死。
- 下文属于整合后的实施建议，随整版确认：一次改选只影响本次保存，不自动改写工作区默认；工作区映射留本机；附件默认勾选和导出打包方式；具体体积阈值。不把这些建议写成已经实现或单独获批。

## 用户操作

### 会话侧栏与继续编辑

- 复用宿主公开右栏 tab 和会话工具入口，不替换其他工具页、不默认抢占侧栏。布局和主题跟随宿主；窄屏空间不足时，可打开现有独立笔记窗口。
- 显示「从本会话保存」「关联的笔记」，提供查找、关联、转存当前会话和打开完整窗口。工作区默认本只是保存位置，不将其中全部笔记自动关联到本会话。
- 点击笔记在侧栏阅读；点击编辑后原地修改标题、摘要、标签、笔记本与正文，复用现有 Markdown 编辑器和自动保存，不维护第二套编辑器；工具栏按宽度收纳。
- 转存成功后，**本机保存完成就刷新侧栏并选中新笔记**，可继续编辑；不等待 GitHub 同步或可选标题/摘要/标签建议完成。仅在该会话侧栏仍打开时选中，不展开已关闭的侧栏，不覆盖已切换的另一会话。
- 会话切换、关闭侧栏、打开完整窗口沿用自动保存；所有界面共用按篇编辑保护。同篇在另一窗口编辑时可阅读并提示占用，不同时写入。编辑只改笔记正文和信息，不改原始素材。
- 一篇笔记可手动关联多个会话；解除只移除关系，提供撤销，不删除笔记。来源组保持原始来源事实。关联便于查找，不代表模型已读取笔记。

### 选择笔记本

- 转存始终可选择任意有效笔记本；优先预选工作区对应本，否则用私人库默认本。
- 有工作区时提供“为当前工作区新建”，建议名称取工作区名称并允许修改；也可明确指定一本已有本作为该工作区默认。
- 未分组会话提供普通“新建笔记本”，不建立会话专用映射。
- 偶尔改选只影响此次转存，更改工作区默认是明确操作；对应本被移除时退回私人库默认本，不阻止保存、不自动新建替代本。
- 工作区本仍在同一私人库内，不额外建立 GitHub 仓库，也不在工作区里另建笔记存储目录。

### 保存和导出时选择图片与附件

- 先选当前问答、多轮或整个会话，再展示范围内材料。会话下方已有保存、导出按钮与侧栏入口共用选择组件和服务端规则。
- 默认勾选范围内可用图片和文件，允许逐项取消、全选/全不选，显示名称、类型、大小和合计。无附件时隐藏该区域，不增加必经步骤；超过提醒阈值时集中提醒一次。
- 用户上传文件跟随所属消息；AI 正式交付文件显示为“本轮交付文件”，按消息细选时仍可单选，不猜属于哪段回答。仅提及的路径和未交付的工作区文件不自动归档，不扫描工作区。
- 保存时复制所选材料；图片显示在正文中，普通文件提供下载。取消选中的材料不偷偷归档，生成内容标明“未包含”，避免留下看似可用的本机链接。失败项可取消或明确跳过后继续，不假报完整保存。
- 用通俗说明提示文件版本：“如果 AI 后来修改过这个文件，这次保存的是修改后的内容。保存到笔记后，原文件再变也不会影响这份副本。”不为此建设工作区文件历史系统。
- Markdown 仅文字可导出单个文件；包含所选图片或附件时打包，正文用相对路径。PDF/长图/多图展示文字和所选图片，普通附件只显示名称；要带走普通附件时，把生成文件和附件一起放入 ZIP，不声称音视频已嵌入页面。
- 笔记内导出复用附件选择和格式说明；选择只影响此次导出，不修改笔记、不删除库内材料。整库导出的逐文件精细选择不在本批扩展。

### 引用到当前会话

- 首次范围为单篇，可选择带入的图片和普通附件；先完成自动保存，再准备这个已保存版本的副本。
- 调用宿主附件服务保存副本，改写材料内部引用，通过公开输入接口加入简短读取说明；保留已有文字和附件，支持撤销，不自动发送。
- 只针对有效会话和可用输入框；准备期间输入或会话变化时停止插入、提示重试，不覆盖新草稿。只处理用户选中的笔记和合法附件，不扫描其他私人资料。
- 文案用“引用到当前会话”“已加入读取说明”，不称“已附加到附件栏”。关联和引用分开，不因打开侧栏就把内容交给模型。
- 副本由 DSH 管理，不在工作区建立中转目录；修改笔记、搬迁笔记库不改变已引用副本。首版核验本机 Windows，不承诺 WSL/远程路径通用；不支持的执行环境明确提示。
- 不自行清理宿主附件目录，不为此增加跨设备同步。原生附件栏能力按主规划[接口复查备忘](2026-11-09-product-iteration-roadmap.zh.md#宿主接口开放后补齐直接附加)在宿主升级、E 后回顾及 F 规划时核查并提醒。

## 数据与实现取舍

| 项目 | 推荐做法及原因 |
| --- | --- |
| 侧栏与编辑 | 公开 tab + 现有阅读/编辑组件，避免覆盖宿主或维护第二套编辑器。 |
| 来源与手动关联 | 来源继续由 sourceId 推导；手动关系作为可选笔记元数据，沿用修订和同步。关联会更新笔记修改时间，不另建关系数据库。 |
| 工作区默认本 | 用宿主公共工作区身份，映射按私人库身份隔离，存插件本机配置；不按名称/路径猜关系，不要求不同设备有同一 DSH 工作区。 |
| 文件选材 | 服务端冻结范围，客户端只提交选中项身份；服务端核对消息/轮次归属、路径、体积和读取结果，不开放任意本机路径读取。 |
| 文件保存 | 复用图片/普通附件存储、共享引用和彻底删除规则；原始素材与可编辑正文分开。引用到会话的副本用宿主公共附件服务。 |

- 查询排除模板和回收站，恢复后可显示；普通编辑、换本和历史正文恢复保留当前关联。复制及从模板新建不继承手动关联，已有来源保留规则不变。
- 便携导出不携带宿主会话编号或本机工作区映射；导入不按任意编号建关系。另一设备没有原会话时仍可阅读笔记，不重建会话或跳转同名会话。
- 关系及来源附件结构变化须更新格式识别、读取/保存/同步校验；旧包不得忽略新字段后写回，同库实例使用匹配版本，不预建复杂兼容框架。
- 写入复用版本检查、队列和编辑占用。偶发多端冲突继续保留两篇供用户取舍，不增加专用合并系统。
- 取消停止后续工作；已导入笔记保留并报告，正在提交的单篇按原子保存完成或失败，不假装取消会撤销全部已完成结果。

## 体积与性能：只围绕常见使用

用户明确本插件以会话材料、日常笔记为主；**本轮限制评估的重点是图片与普通文件的单个大小、合计大小和数量，文字只保留基本检查，不作为容量测试主线。** 不将百万字文章、几百兆至 GB 文件作为常见场景。先参考竞品公开说明，再做少量针对性测试；不开展代表所有电脑的硬件评测，不为极端规模重建架构。

| 当前 0.8.0 规则（尚未修改） | 衡量内容 |
| --- | --- |
| Markdown 单篇 10 MiB | 文件本身的字节数，含文字、属性、链接地址，不含另存的图片/文件。正文保存也有 UTF-8 字节上限。 |
| 图片单张 5 MiB、合计 20 MiB | 图片文件的字节，不等同于像素数或显示时的内存开销。 |
| 普通附件超过 10 MiB 确认、超过 50 MiB 拒绝，每篇合计 200 MiB | PDF、音频、视频等下载型文件，不要求编辑器解析其中内容。 |
| 文件夹/ZIP 每批 200 MiB | 纳入本批的文件总量；ZIP 还检查解压后的大小，不能只看压缩包有多小。 |
| 单篇最多 128 张图片、128 个普通附件 | 两类分别计数，是当前实现的保护值，不是已测定的性能极限。 |
| 导入批次最多 10,000 项、5,000 篇笔记 | ZIP 项计数还会涉及目录项；文件夹扫描按纳入项计数。用于保护批量处理，不作为常见验收规模。 |
| 笔记数据目录累计 512 MiB；库内最多 5,000 篇 | 512 MiB 检查覆盖 `notes/` 下正文、修订、素材、图片和附件等实际文件，不含仓库的 `.git/`；远端快照读取也受累计限制。5,000 篇按保留修订的不同笔记 ID 计数，含回收站和模板，不是每个笔记本各有 5,000 篇。 |

这些具体数值不是已测定的流畅运行边界，前期切换测试也不能证明上限附近流畅。竞品对照与小测另附记录。建议方向是普通文件向 GitHub 普通仓库规则靠拢（超过 50 MiB 提醒、超过 100 MiB 拒绝），取消缺少必要性的每篇普通附件总量硬限制；图片保存/预览、批量导入阈值结合参考和小测一起定。此为待审建议，不是本轮已经改动；必要的解析、ZIP 展开、文件数量和路径保护仍须保留具体依据，不简单删除全部检查。

**不能把上述改进解释为“只受 GitHub 限制”或“总容量不限”。** 512 MiB 是插件目前的整体扫描/快照保护值，涉及内存和保存，不是 GitHub 规定，也不是实测得到的合理库容量。日常逐步积累也可能触及，不将它当作只有极端大文件才会遇到的问题。E2 在修改限值前统一核对上传、图片显示、保存、导入和同步各层；明确提出保留/调整及用户提示，避免前端接受后端拒绝。此项仍需收口，不能只放开单个附件便宣布容量问题解决；不在本轮未经验证地取消整体检查。

参考及小测见[补充记录](2026-11-10-e-import-size-reference.zh.md)。图片/文件四种场景各测 5 次：1/8 MiB 文件前端准备、8 个约 1.9 MiB JPEG 解码、50 篇加 16 项媒体的 ZIP 解压扫描。常见环节中位数约 23–173 ms，仍有约 0.18 秒的同步任务；结果支持先处理必要的分批和让出执行时间，未证明完整导入/保存/同步或较大上限附近流畅。已做的 1 万/5 万字符转换只作为附带记录，不再扩大文字测试或进行极端压力测试。

正式验收要求：

- 当前隔离小库基础上验证相关列表、切换、普通图文和几十项材料的小批次；既有长文只做编辑功能抽查，不再将百万字或 1000 篇合成库压测列为本批强制门槛。
- 列表只取摘要，不预读全库正文/图片、不逐篇扫描全部会话；索引随内容变化失效。隐藏侧栏停止刷新，不重复触发 Git 同步，本机阅读不等待网络。
- 常用操作目标约 0.2 秒内有可见反馈；热切换/普通阅读中位数约 300 ms 内、最大约 500 ms 内，首次相关列表约 1 秒内。实际内容显示与“已开始处理”提示分别测量，不用转圈冒充加载完成。
- 较大处理显示当前文件、已完成数量/总量、提供取消；优先分批或后台处理，尽量允许继续会话工作。持续数秒可以解释，长时间不能点击、滚动或取消不合格；未知总量时报告已完成项，不编造百分比。
- 不为每个小文件传输建立任务中心或永久任务日志；按需把耗时解析、解压移出界面线程，不预建通用作业平台。

## 实施顺序与交付

| 步骤 | 工作内容 | 完成条件 |
| --- | --- | --- |
| E0（接口已补验，本轮整合规划及小测） | 后续决定、竞品限制参考、常见规模小测 | 区分事实、建议、未覆盖；整版审核后再开发。 |
| E1：侧栏与组织 | 入口、相关列表/搜索、来源/手动关联、侧栏编辑、工作区默认本 | 转存后本机立即出现；窗口编辑保护一致；不串会话；任意本可选、归属可改；映射和关联重启恢复。 |
| E2：材料流转 | 保存/导出附件选择、普通上传和交付文件转存、单篇引用、必要体积及进度处理 | 文件原样保存，范围与导出说明一致；原件变动不影响副本；输入不被覆盖、不自动发送；失败/取消明确。 |
| E3：集中验收 | 回归、真实宿主、私库同步、性能；文档/截图/体验入口 | 用户集中体验；Agent 主动回顾候选清单和原生附件接口；发布另行确认。 |

工作量中等偏大，按三个批次推进。复用存储、编辑和导出，不重做架构；E2 采集结构、选材、打包及 E1 保存/关联联动是主要工作。整版获批后连续完成，不要求用户逐项提醒；实质范围变化再讨论。

## 影响面、验证与回退

- 客户端：入口、新侧栏/关联视图、编辑控制器、NoteCapture、CaptureSelection、ConversationExport、NoteExport、导入/附件进度；共用组件和限定样式。
- 数据：contracts/notes、notes 下采集/来源/校验/修订/导入导出/删除/同步；工作区映射放 private-workspace 相关本机配置，不写用户工作区。
