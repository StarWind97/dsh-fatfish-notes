## 实现

同步安装时先核对已有资源，复用内容校验成功且文件身份、大小、纳秒级修改/变更时间均未变化的结果。未变化资源不再逐项扫描整库、比较完整文件或二次读取 Git 对象。远端快照的完整性校验仍执行；没有把「本机有同名文件」当作内容正确。

缺失资源在仓库队列外加载并核验，按最多 4 个资源、累计 8 MiB 分批进入队列；单文件超出批次预算时单独处理。每批结束主动让出队列，正式合并前验证最新本机状态与依赖。全局队列优先级、同步频率、存储格式、用户入口、依赖与身份/来源校验不变。

同一批内相互独立的只读校验并发执行，出错时等待本批检查全部结束再退出；写入仍串行且受原仓库队列保护。新增模块 `src/notes/sync-resources.ts` 只接受不可变图片、来源快照与附件路径。

初版把同步接收缩短到约 3 秒，但五次预览完成反而为 2755 / 3737 / 2834 / 3257 / 3208 ms，中位 3208、最大 3737 ms。实测没有通过后，继续修正两处本轮接收尾部的重复工作：只有实际待删除文件才延期清理，避免旧墓碑每次使缓存失效；无新修订且所有本机正文均有效、对应最新版本时，复用刚验证的本轮快照，不再完整合并和再次导出。缺失/旧版正文、外部改动、损坏与新修订仍走完整处理；未增加长期缓存。初版失败记录保留为 `after.json`，不计为最终达标证据。

上述修正后、批内只读检查并发前，五次为 1577 / 1657 / 1603 / 1750 / 1668 ms，中位 1657、最大 1750 ms，仍未达到 1500 ms 中位目标。中间记录 `after-final.json` 保留，最终代码对应后文的 `after-verified.json`，没有合并多组或挑选较快样本。

资源在本轮安装期间临时保留。取消草稿若遇到仍在同步中的共享文件，将延期清理路径写回原有持久回执；永久删除的墓碑立即生效，物理清理保留日志直到安装结束。成功、失败或取消时解除保留，按实际引用清理，失败重试保持幂等。换库后的迟到接收不得写入新资料夹。
