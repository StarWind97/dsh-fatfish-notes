# 笔记读取与切换性能优化

状态：2026-11-10，本项已完成同一资料的前后实测与集中体验，作为 A—D 验收修正统一随 0.8.0 发布，未单独发版。实测见[性能交付](2026-11-10-performance-results.zh.md)，公开包结果见[发布记录](../releases/0.8.0/review.zh.md)。下文保留实施时的范围、目标和验证规则。

## 范围和取舍

- 复用已经校验且文件未变化的仓库结果，避免每次点击重复读取全部历史和附件。保留路径、身份、结构、哈希及损坏数据检查；保存、同步、删除、换库和失败后必须重新核对。
- 减少切换筛选时重复查询笔记本、初次轮询重复刷新和过期请求。列表与内容及时显示，不等待无关结果。
- 避免未变化的正文随状态轮询重复渲染。不改变笔记格式、不引入数据库或新依赖。
- 选用有文件变化检查的轻量缓存；暂不引入文件监听服务、常驻索引或仅按时间过期的缓存。

影响 `src/notes/` 的读取与验证复用、`src/client/` 的请求和渲染、相关测试及协作文档。预计为中等规模改动。主要风险是缓存过期和跨窗口显示旧内容，需覆盖实际变化与失败；回滚可恢复之前源码和内部安装包，资料格式保持兼容。

## 验证和交付

1. 修改前记录同一隔离资料的数量、版本、接口耗时及实际界面加载、笔记本切换、普通/长文切换耗时。区分首次加载与热切换，不混入宿主启动时间。
2. 加入重复读取及变化失效的回归，验证保存、历史、同步导入、删除、外部文件变化及双窗口；运行第三档检查：类型检查、构建、全量回归和实际安装。
3. 安装优化包后重复同一操作，记录样本数、中位数和最大值。常规热切换目标约 100–300 ms，长文约 500–800 ms，首次内容加载约 1–2 s；这是优化目标，不预先宣称达标。
4. 将真实性能结果、未覆盖边界、安装包与重启入口集中交付；提交同步 main，不自动对外发布。

性能进入规划、开发和验收，但按影响范围选择测量：纯文档无需性能测试，局部样式无需全量基准。涉及列表、读取、渲染、后台刷新、保存或同步时明确成本与规模，改前测基线，改后同口径对比，不能用牺牲正确性换速度。

## 可重复的读取基准

构建后可运行 `node --import tsx scripts/measure-notes.ts "<隔离资料副本根目录>" "<笔记 ID>"`。目录下须已有 `notes/`，只使用已初始化的测试副本；需要迁移或写入时脚本停止。可选第三个参数指定旧包的 `lib/notes/repository.js`，以同一份资料比较两个版本。

输出包含资料哈希、笔记/修订/文件数量、一次进程内首次读取、五次热列表/笔记本/正文读取及文件读取次数、字节数。这里的“首次”是仓库缓存首次建立，不代表操作系统磁盘冷启动；该基准也不能替代窗口从点击到绘制完成的测量。实际 UI 另用隔离 DSH 与临时 Chrome 窗口测试，两者均复用同一服务。
