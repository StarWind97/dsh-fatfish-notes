# 粘贴与拖放交付记录

2026-11-12：按[已批准规划](2026-11-12-paste-and-drop.zh.md)完成实现，进入用户验收。本轮仍是未发布的 E 候选。

## 已实现

- 正文接收混合图片和普通文件，按输入顺序分别内嵌图片、插入下载链接，不再遗漏混合粘贴中的图片；整批正文插入可一次撤销。
- 补充附件区可拖放文件，点击区域后可粘贴；有焦点边框和操作提示。图片也作为文件卡片，不修改正文。
- 文件选择器继续保留。常规文件直接添加，大文件沿用原有确认和上限；确认后关闭弹窗，后台 Worker 分块处理，所在区域显示进度和取消。
- 多批次按顺序处理，期间输入不会被覆盖。取消传输保留完成项；取消编辑仍放弃整次草稿。没有增加文件限制、依赖、存储协议或宿主权限。

## 耗时及尚未确认的边界

同一隔离宿主、1660 × 1100 窗口，每组连续粘贴并撤销五次：

| 样本与完成条件 | 五次耗时 ms | 中位 / 最大 |
| --- | --- | --- |
| PNG + 文本，共 140 字节，正文两项出现且进度结束 | 877、895、600、646、605 | 646 / 895 ms |
| JPEG 照片 + 文本，共 51,171 字节，两项插入且照片完成预览（首轮） | 11,425、2,945、3,126、2,995、2,761 | 2,995 / 11,425 ms |
| 同一照片 + 文本，明确将隔离窗口置前后复测 | 6,968、5,496、6,049、9,792、2,702 | 6,049 / 9,792 ms |

照片首轮未锁定前台，随后测量曾被用户切换页面打断；已撤回脚本误插入的文字。用户明确暂停操作后，重新选择体验笔记并确认窗口前台，再完成上述五次复测。另一次测量脚本误把 CodeMirror 无源占位元素计入图片等待，修正为只看正文图片后采样；不计入超时结果。

复测证据表明延迟并非只有后台节流：正文插入耗时分别为 6961、5488、6038、9780、2689 ms，图片预览只比插入晚 7–14 ms。主要等待在本机草稿请求（部分超过 1 秒）与每个文件开始/分块/完成的串行请求（多数约 0.5–1.6 秒）；Worker 启动请求约 49–89 ms。请求等待已定位，进一步区分宿主转发、仓库队列和磁盘读写仍需专项测量，不能直接把总耗时归咎于图片解码、电脑速度或 GitHub 网络。

**下一轮优先处理文件接收等待**，在保留草稿、路径、身份和跨窗口编辑校验的前提下分析重复往返及排队。本轮未改变这些保存边界。当前可继续编辑并可取消处理，但不宣称照片添加性能达标；小文件数据不代表大文件速度。旧版混合粘贴不能完成相同输出，因此不计算提速比例。

原始证据：`.dsh-home/pure-001/clipboard/` 内的 `baseline.json`、`native-before.json`、`ui-results.json`、`extras.json`、`final-check.json`、`handoff.json`、`foreground-timing.json`；截图在 `output/playwright/clipboard/`。

## 用户体验

入口：[打开肥鱼笔记](../../scripts/Open-Fatfish-Notes.cmd)。当前隔离窗口已保留在体验示例阅读态，供用户操作。

1. 打开「正文与补充附件」笔记本中的「复制粘贴与拖放 · 体验」。
2. 进入编辑，从 `.dsh-home/pure-001/clipboard/experience-files/` 同时复制照片和文本文件，粘贴到正文，检查图片与下载链接；也可直接拖入。
3. 点击下方补充附件区后粘贴其他文件，检查独立卡片；不要把正文已经使用的相同文件误当作新的补充项。
4. 试试撤销、取消编辑，以及完成编辑后的阅读效果。测试材料可自行替换，不涉及日常资料。
