## 实现与试验修正

保留 TypeScript / Node / Electron 和原 Markdown / JSON / Git 格式。新增可重建的内存文件目录，热态操作处理相关路径和变化，不再先遍历全部文件才能命中缓存。当前笔记、历史依赖和控制清单仍直接核对文件身份、体积与纳秒级变更时间；监听只提示变化，未知通知、监听失败、根目录替换及异常会触发重建。超过 30 秒后的下一次访问审计全库；同步导出和物理资源清理继续完整审计。缓存不持久化，无法监听时退回保守扫描。

未保存草稿资源不再重算正式清单，也不使正式笔记图缓存失效；实际被历史引用的资源仍参与缓存身份。窗口状态和心跳不再等待仓库长任务，取得/释放/交接编辑资格和真正写入仍由原队列排序检查。没有解除写入保护，也没有让读取看见未完成合并。

远端同步复用整份快照已验证、路径与 Git 对象身份不变的数据。缓存绑定同一仓库与本机资料根，文本最多 32 MiB、全部最多 10000 条；图片和附件只保留校验收据，不长期保留二进制内容。失败/取消清空复用，变化或换库/换根重新校验；远端图、清单、引用、私有性与账号校验继续执行。

实施中保留了两次重要修正：Windows 删除监听根目录后会不断发送绝对根路径通知，必须立即关闭失效监听；延期删除不能只使用热态索引，须在解除同步保留后完整审计，保护另一写入者已发布但尚未更新清单的有效修订。后一项新增故障用例先失败、修正后通过。第一轮索引虽已减少扫描，1000 篇文件接收中位仍为 439 ms；排除未发表资源造成的正式图失效后，最终降至 90 ms。过程及失败日志均留在规划记录中。

收尾还补测了无通知时的笔记本变更与恢复：确认改名可能漏检损坏文件后，将笔记本修改、删除和显式恢复这三个低频入口保留为完整审计。新增远端修订的本机祖先损坏用例也通过。没有为了速度放宽这些写入和恢复检查。
