# 0.10.0 公开说明补齐与后续维护

2026-11-20，用户要求查明 README 展示与产品脱节的原因，修正受影响的内容，并在今后的改版中主动同步。目标与已发布的 0.10.0 对齐，本轮交付为仓库文档、展示资源和维护规则。

## 原因

- [11 月 18 日品牌接入](2026-11-17-berry-brand-adoption.zh.md)把旧提亮绿组合复制到独立路径，以保留当时获准的公开展示。[品牌规则](../brand.zh.md)当时只说获准后再换，缺少负责跟进的人、触发时点和发布待办。
- 原用户文档规则重点覆盖随包手册与在线图解，宣传图要求放在另一节。两项规则缺少同一份变更影响清单，也没有在全流程验收时把 README、浅深 Logo 和截图清单逐项带入。较大版本虽有重评宣传图的要求，缺少逐张核对后才能沿用的完成条件。
- [0.10.0 发版规划](2026-11-20-release-0100.zh.md#正式发布)更新了 README 版本、安装、局部功能文案，采用已验收的新版手册和图解实拍，同时沿用既有介绍图。发布记录可以追溯安装和手册验证，缺少四张旧图与 0.10.0 界面逐项比对的结果。

## 范围与做法

1. 两份 README 共用现用透明 Logo 的浅深资源，减少维护副本。保留旧展示图的历史路径。更新 0.10.0 的阅读标签、统一查找、会话侧栏和分类核对文案，并链接有详细步骤的图解。
2. 沿用已接受的展示场景，用正式安装的 0.10.0 在隔离 DSH 重拍，按新版实际界面和取景质量调整。两份 README 和 `screenshots.json` 使用同一组素材。已有新版图解为标签核对等详细操作提供实拍。复核手册、图解、详细参考及产品设计与当前版本的一致性，对确认的漏项补齐或记明处置。
3. 在 `AGENTS.md` 给改版规划、验收与发版增加统一入口。细则沿用展示内容准则，明确受影响材料、负责人、候选与正式版本的切换时点和完成证据。单设定期检查只能事后发现遗漏，本轮将核对放进每次变更及发版流程。

预计一轮复拍和图文核对，再核验线上呈现。用现有测试资料和已编排的展示内容，排除账号、非演示会话与私有库标识。按原尺寸及 GitHub 常见正文宽度查看，核对中英文图注、链接、浅深资源和公开截图清单。风险集中在截图误导、图文不同步和回退时引用丢失。可用后续回退提交恢复原引用，保留旧素材和已经发布的版本记录。
