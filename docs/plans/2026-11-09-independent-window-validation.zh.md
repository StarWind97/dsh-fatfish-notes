# 独立窗口小范围验证

状态：2026-11-09 已完成获批的小范围验证。结论：同一 DSH 服务上的浏览器应用窗口可行，能满足笔记与会话并行使用；正式窗口功能仍需补齐下述边界。完整三栏界面及正式窗口功能尚未实施。

后续已按用户确认规则形成[自适应三栏与独立窗口正式规划](2026-11-09-adaptive-layout-and-independent-window.zh.md)，当前只落盘待审核，未进入实施。本文保留原型验证时的实际结果，不将后续规划改写为已验证能力。

## 目标与范围

确认肥鱼笔记能否作为单独窗口使用，同时 DSH 主窗口继续停在会话。验证复用现有笔记服务、阅读与编辑、自动保存、关闭后恢复，以及会话转存的新笔记可见性。

本次只在 `.dsh-home/pure-001/` 构造临时入口，复用 0.7.0 界面与后端。不开新存储，不改变笔记格式和同步协议，不实现正式三栏布局、会话侧栏或 AI，不发布新版、不修改日常资料。

## 方案取舍

| 方案 | 判断 |
| --- | --- |
| DSH 原生子窗口 | 安装的 0.2.2-rc.1 会拒绝 `window.open` 创建子窗口，HTTP(S) 转交系统浏览器；preload 没有公开通用开窗接口。暂不能作为插件公共能力承诺。 |
| Chrome/Edge 应用窗口 | 首选验证。独立显示笔记页面，调用同一个 DSH Host 的现有接口；DSH 仍须运行。 |
| 修改 DSH 的 Electron 安装文件 | 不采用；升级需反复适配，超出插件应承担的维护范围。 |
| 第二个 DSH Host 写同一资料 | 不采用；增加并发写入与同步争用，现有单写者保护也不允许。 |

依据：[官方桌面入口](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/desktop/src/main.ts)、[preload](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/desktop/src/preload-app.ts)及本机 0.2.2-rc.1 安装包源码。官方 master 会继续变化，本结论针对核查时版本。

## 影响、风险与回退

正式源码不改；在隔离资料中临时注册页面路由、构建复用 React 界面的入口、使用独立 Chrome 测试资料。仍使用既有 loopback、Origin 和 sec-fetch-site 栅栏，不读取或搬运登录凭据、不放宽浏览器安全配置。

需要检验多个窗口的内容刷新、焦点切换、关闭时未完成保存及 DSH 退出边界。正式实现还需定义窗口复用、主题跟随与同篇多窗口编辑规则。验证不承诺跨平台及任意多窗口同时编辑。

结束后移除隔离 profile 的临时扩展配置，关闭本轮自建进程；保留可重新执行的测试入口和证据。测试笔记仅写入指定测试库。生产插件、日常资料及公开安装包不受影响。

## 验证与交付

工作量为一个小范围技术验证；构建临时入口并通过真实宿主与浏览器操作核查。不更改生产代码，因此不以全量回归代替实际窗口验证。

交付：更新后的迭代路线、本文件中的实际结果、隔离截图及复现入口。结果区分原组件直接可用、原型补充机制后可用与仍待正式实现的能力。

## 实际结果

环境：Windows / Node 24.21.0 / DSH 0.2.2-rc.1，公开 0.7.0 后端和当前源码组件。使用 Chrome `--app`、独立浏览器资料、现有 `release12-desktop`，绑定指定测试私库；没有复制账号凭据或第二个笔记后端。临时页面通过宿主公开路由注册接口提供，只打包额外的 React 前端。

| 检查 | 结果与证据边界 |
| --- | --- |
| 窗口打开、共用数据 | 通过。应用窗口无普通浏览器地址栏，读取现有笔记；独立窗口新建并自动保存后，DSH 通过原接口读到相同正文和标题。 |
| DSH 会话与笔记并行 | 通过。DSH 主窗口停留在会话，独立窗口可阅读、编辑；未替换主窗口页面。 |
| 关闭后重开 | 通过限定场景：输入后不等 800 ms 自动保存，立即关闭并重新启动 Chrome 应用窗口；同一 DSH 服务地址和浏览器资料下，最后输入保留，回到阅读态。未验证 DSH 与浏览器同时异常退出的恢复。 |
| 实际会话转存与图片 | 通过。隔离 DSH 中使用已有合成会话，经实际按钮保存两条消息；独立窗口能读到正文与归档图片，主窗口仍停留在会话。没有请求模型生成内容或消耗模型额度。 |
| 新笔记自动出现 | 发现缺口后验证补充机制。直接复用原组件，12 秒观察期内列表没有出现新笔记，刷新页面后可见；原型增加每 5 秒仅向本机服务读取、编辑中暂停的刷新后，本次约 2 秒出现。它不是 GitHub 定时同步，也不是生产代码已具备的新功能。 |
| 关闭 DSH | 后端请求实际失败，证实独立窗口仍依赖 DSH。正式版需要清楚的连接提示和重新打开入口；当前原型不算已完成此交互。 |
| DSH 重启 | 本轮服务端口从 61955 变为 61017；再次启动体验入口会使用新地址。旧页面不能自然重连，浏览器按来源隔离的本机恢复记录也不能直接跨新地址使用。 |
| 安全与收尾 | 原笔记接口拒绝带外部 Origin 的请求（403）；没有放宽既有保护。已关闭自建进程，恢复隔离配置与临时会话入口，公开包和日常 DSH 未改。 |

### 正式实现前必须补齐

1. **入口与窗口重用**：插件顶栏提供独立打开；重复点击唤回已有窗口，先只允许一个独立笔记窗口，不建设多文档窗口系统。
2. **跨窗口更新**：使用本机更新通知或轻量读取；编辑期间不替换正文。原型已证明本机读取可行，正式实现再确定最小方式。
3. **生命周期与保存**：DSH 退出或重启后明确连接状态；解决地址变化下的恢复。原型中 CDP 切换前台没有稳定复现「返回即阅读态」，焦点行为尚需专门验证，不算通过。
4. **主题与编辑归属**：本次仅复用了宿主浅色变量的快照；实时深浅色跟随、同篇在两边打开时的编辑规则仍待实现，避免同时编辑产生不必要的副本。

三栏布局不要求改变存储模型。建议下一步先讨论正式开窗与上述必要机制，再制作「笔记本—笔记列表—正文」界面样稿；目录和未来右侧操作面板按需共享空间。窗口方向为高优先级，但不会因此撤销原路线中的搜索、历史恢复和批量整理。
