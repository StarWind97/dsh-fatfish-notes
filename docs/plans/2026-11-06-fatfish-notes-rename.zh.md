## 实施范围

统一界面、包信息、安装注册、前后端模块、接口、配置键、目录标记、写入锁身份、私库格式标记、生成文件中的品牌信息、默认库名、当前文档与市场材料。现有资料一次性转换；运行代码只使用新名称，不保留旧格式或名称的读取分支。通用 note/notebook 概念不改。

GitHub 原仓库直接重命名，保留提交和发布历史，更新 origin 与链接。已发布的旧包、历史截图和当时的验收记录保留，不伪造为新名称。当前 AGENTS.md 更新产品名称和本轮入口，保留实际本地路径与指定测试仓库。

仅迁移项目内 .dsh-home/pure-001 的活动体验资料；云端转换仅限已指定的 StarWind97/dsh-community-private-test。现有私人库名称不自动改名，新建默认使用 fatfish-notes。不修改日常 DSH 资料、宿主和依赖，不重设计图标，不增加产品功能。

## 顺序

1. 落盘规划，记录起点提交并备份活动隔离实例的插件资料；提醒用户暂不使用体验窗口。
2. 统一源码、包信息和当前文档，重新构建。以一次性迁移工具转换本机控制目录、库路径记录、外部资料夹归属标记与浏览器存储键；转换指定私库的品牌格式标记，笔记内容和修订保持不变。
3. 通过宿主移除旧插件、安装新包，真实验证现有资料接续及新初始化。停止旧写入者后再迁移，迁移脚本不进入插件运行路径。
4. 核验后重命名远程仓库，更新地址，中文提交同步 main 并核对 SHA；准备更名后的市场条目和发布审核材料。
5. 交付候选包、实际截图、迁移结果与重启入口，停在发布审核。此授权不包含正式 Release、npm 发布或市场 PR 提交。

## 验证与回退

按第三档执行类型检查、构建和一次全量回归；安装后验证阅读/编辑目录、自动保存、图文读取、会话转存与导出、绑定接续和真实私库双向同步。补充系统目录选择确认；人工操作需要时只提示配合。核对新旧插件不会同时加载，当前源码不遗留旧品牌标识（本地路径、迁移工具和历史资料除外）。

迁移前记录配置、文件摘要与远端修订。失败时用备份恢复对应控制资料、原安装包及私库标记；代码通过回退提交恢复，不重写 Git 历史。迁移结束仅新目录作为活动资料，备份留在忽略目录。

工作量为一次中等规模整理，主要时间用于安装与验证；不建设长期兼容框架。
