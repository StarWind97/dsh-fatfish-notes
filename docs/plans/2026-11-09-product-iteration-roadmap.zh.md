# 肥鱼笔记常用功能与迭代参考规划

状态：2026-11-09 用户已接受依据语雀补充资料调整路线，并先验证独立窗口。获批范围为本文更新和[独立窗口小范围验证](2026-11-09-independent-window-validation.zh.md)；三栏正式界面及以下功能批次仍需单独确认，不将本文视为全部功能的实施授权。

后续规则已确认并另行落盘[自适应三栏与独立窗口正式规划](2026-11-09-adaptive-layout-and-independent-window.zh.md)：宿主内与独立窗口使用同一自适应布局，双窗口按篇保护编辑。当前只获准整理规划，功能实施仍待用户允许，按五个步骤分别验收和停顿。

本轮验证已完成：Chrome 应用窗口复用同一 DSH 服务可行；自动保存、同地址关闭恢复及会话图文读回通过，原型补充本机读取后新笔记可自动出现。正式功能仍需补齐生命周期、主题跟随和编辑归属，详见上述验证记录。

基线：肥鱼笔记 0.7.0，源码 `d555e43303d16818244605c15a98ed078767daaa`，DSH 0.2.2-rc.1。当前行为以[产品设计](../notes-design.zh.md)和[使用说明](../user-guide.zh.md)为准。本文记录调研时的状态，不随未来版本自动变成已实现清单。

## 目标与取舍

维持现有架构，先验证不打断 DSH 会话工作的独立窗口，再补齐查找、整理和恢复，随后强化会话关联，最后发展有明确用途的 AI 功能。优先把日常操作和外观做好，不按竞品功能数量扩张产品。

当前仍定位私人笔记管理：以 Markdown 和普通附件保存内容，通过自己的 GitHub 私有仓库同步；不改成块级数据库，不引入团队协作，不与其他软件共同编辑内部仓库。正文继续由用户手动编辑，现有模型建议仅用于会话转存时的标题、摘要和标签。

本文交付竞品依据、现状与缺项、优先级、分批路线和实施边界。独立窗口验证使用隔离资料中的临时入口，不代表正式功能已交付，不启动新版发布。

## 优先级与分批路线

### 必要性与可行性取舍

| 能力 | 对 DSH 笔记插件的必要性 | 现有基础与维护负担 | 决策 |
| --- | --- | --- | --- |
| 独立窗口 | 用户可边会话边阅读和编辑，直接解决主界面互相占用。 | React 界面与本机接口可复用；宿主没有公开的原生子窗口接口，需验证浏览器应用窗口及生命周期。 | 当前先验证，通过后单独确认正式实施。 |
| 收藏、最近访问、基础搜索增强 | 高频查找入口，价值明确。 | 稳定 ID、现有全文搜索可复用；最近访问留本机。 | P1，复杂筛选随后加。 |
| 历史恢复、批量移动、标签选择建议 | 减少误改损失及重复操作。 | 已有不可变修订、多选和笔记本；需要补界面与接口，风险可控但写入必须验证。 | P1；标签合并不与第一批捆绑。 |
| 会话相关笔记侧栏 | 快速找到本会话材料，仍有价值。 | 来源资料可用，宿主公共接口及右栏共存仍需验证。 | P2；不是并行阅读的唯一途径。 |
| 反向链接、轻量模板 | 内容积累后有用。 | 可基于 ID 链接和复制实现，无需改变存储。 | P2，逐项实施。 |
| 多篇合并成新稿、AI 分析输出 | 需要用户选择资料和具体输出目标，不能仅因竞品具备就开发。 | 合并涉及来源、附件、重名和引用；AI 另需宿主接口及交互设计。 | 备忘；等实际场景明确。 |

语雀的[小记](https://www.yuque.com/yuque/help/vbtstk)与[知识库目录](https://www.yuque.com/yuque/thyzgp/vlki63)提供收集、整理和多栏导航的参考，但不据此引入另一个碎片内容系统、层层嵌套目录或团队权限。

按核心任务价值、重复操作频率、现有基础复用程度和持续维护负担排序。P1 为优先补齐的基础体验；P2 为随后发展的组织与会话能力；P3 为依赖场景和接口验证的后续方向。工作量是相对判断，不是工期承诺，正式实施前再拆分。

| 批次 | 建议内容 | 最小交付结果 | 工作量 |
| --- | --- | --- | --- |
| 贯穿各轮 | 保存/同步问题、长文及较多笔记的响应、菜单弹窗与空态、键盘操作一致性。 | 真实问题优先，先测量再优化；外观与可用性纳入每批验收。 | 持续、小批 |
| 前置验证：独立窗口 | 同一 DSH 服务中的笔记窗口与会话并行。 | 验证打开、保存、关闭恢复及会话新笔记可见性，再确定正式方案。 | 小；正式实现另估 |
| 第一批 P1：查找 | 收藏、最近访问、搜索增强、标签选择建议。 | 常用内容快速打开，结果解释命中位置。 | 中 |
| 第二批 P1：整理与恢复 | 历史版本入口、批量移动、批量增删标签、复制笔记。 | 一批笔记无需逐篇整理，改错后可自行恢复。 | 中，涉及写入和同步 |
| 第三批 P2：会话复用 | 会话相关笔记侧栏、手动关联、来源信息；验证直接附加。 | 在会话旁找到并使用所需笔记。 | 验证小，完整实现中到大 |
| 第四批 P2：关联与复用 | 反向链接、链接预览、轻量模板、保存常用筛选。 | 展示内容关系，减少重复劳动。 | 中，可逐项拆分 |
| 第五批 P3：AI 输出 | 选定资料生成提纲、对比、汇总或新稿，保留来源。 | 用户选择材料与目标，结果预览后另存。 | 大，另行规划 |

批次不直接绑定版本号。先完成独立窗口验证，再确认正式窗口与第一批的先后安排；历史版本恢复仍为紧接着的重点，不因新增窗口方向推迟基本可靠性工作。

### 独立窗口与布局方向

保留宿主内入口；独立窗口承担完整笔记工作，会话侧栏以后承担当前会话的相关材料快捷入口。先尝试浏览器应用窗口，不修改 DSH 安装文件，不另开一个服务同时写同一资料夹。

已确认「笔记本列表 → 笔记列表 → 阅读/编辑」三栏适用于两种窗口，由笔记区域的实际可用宽度决定；笔记本栏可折叠，窄窗回到下拉选择，两种窗口分别记住本机布局偏好。最右侧目录与未来操作面板按需显示、共享空间。双窗口不整体禁止写入，但同篇笔记只允许一处编辑，交接前完成保存；具体步骤与验收见正式规划。当前尚未实施。

### 第一批：更容易找到

- 收藏与置顶先选一种，推荐收藏配一个筛选入口，避免同时引入近似概念。收藏适合跨设备同步，具体存储方案在实施规划中确认。
- 最近访问与最近修改分开。访问记录先保存在本机，并按笔记库区分，避免每次阅读触发同步。
- 搜索先支持多关键词、标题命中优先、命中上下文、高亮和定位。日期、有图片/附件、无标签等条件优先通过界面点选；不先建设复杂查询语言。
- 多关键词与结果上下文先做，组合筛选按需要补；不把全部搜索条件塞入首批。
- 输入标签时显示已有标签和数量；暂不增加多级标签体系。
- 保持现有布局和列表摘要风格；常用操作清晰可见，筛选按需展开，不将所有入口堆到顶部。

### 第二批：更容易整理和恢复

- 历史入口提供按时间排列的列表及预览。恢复旧内容时创建新修订，保留恢复前版本；可另提供恢复为副本。先不做逐字差异合并。
- 复用多选完成批量移动和标签操作。标签区分添加、移除，不覆盖每篇笔记原有的其他标签；全选范围仍应清楚显示。
- 复制笔记先满足样板复用，再决定模板管理器。
- 标签统一改名、合并可在基本批量操作稳定后补齐。

### 第三批：在会话中继续使用

- 展示从当前会话保存的笔记，允许手动关联已有笔记，并可在侧栏查看、搜索和打开。
- 来源关系与使用关系分开：笔记可以来自一个会话，也可以用于多个会话。跨设备笔记可阅读，但原会话未必存在，不承诺总能跳回原会话。
- 先验证宿主公共侧栏接口及与已有右栏的共存方式，不替换或侵占其他功能。
- 调研时安装的 DSH 0.2.2-rc.1 类型中，`ConversationController.createDrafts` 存在附件创建流程，`InputActions.addAttachments` 可加入已登记的附件 ID；但公共 `IConversation` 未暴露完整创建能力。不能把内部方法存在视为插件集成已可行，也不采用绕过公共接口或修改宿主内部代码的方案。
- 直接附加需完整验证文件创建、上传、草稿、图片、取消和会话切换；不自动发送消息、不覆盖已有输入。接口不满足时继续留作备忘，不新增此前已暂缓的「下载后手工附加」产品入口。

### 第四批：关联与重复利用

- 反向链接先回答「哪些笔记引用了这篇」，从现有 ID 链接计算，无需维护第二套手工关系。
- 内部链接提供按需预览，减少来回跳转；不预建图谱或块引用。
- 模板先支持从笔记保存、从模板新建，加日期和标题等少量变量，不支持脚本执行。
- 保存筛选条件等用户确有重复操作后再加入。

### 第五批：有明确目标的 AI 输出

例如：选择三篇笔记，指定「比较方案差异」，交给 DSH 生成结果，用户检查后保存为新笔记。

宿主负责模型和会话，肥鱼负责选材、来源和成果保存。保留现有来源资料，不恢复笼统的 AI 整理正文，不自动覆盖原文。模型调用、材料范围、额度消耗及结果采用应清楚可控。暂不建设独立聊天系统、向量数据库或全库自动分析；语义搜索等普通搜索确实无法解决实际问题后再评估。

## 备选与不纳入近期范围的能力

| 能力 | 处理建议 |
| --- | --- |
| 字数、快捷键说明、复制代码按钮、表格编辑便利性 | 若成本较低，可随相关页面完善；仍按当批确认范围实施。 |
| 追加会话到已有笔记 | 有价值；先明确多次选材及原始素材保留方式，再单独设计。 |
| 多篇笔记合并为新稿 | 参考语雀小记，但先留备忘；明确材料顺序、来源和附件后再决定，不覆盖原笔记。 |
| 归档、手动排序、嵌套笔记本 | 等真实整理需求增长后决定。 |
| 附件管理、库体积统计、备份恢复向导 | 有价值，先做可理解的统计与恢复。整库 Markdown 导出不包含完整内部历史和配置，不等同于完整备份。 |
| 网页剪藏、OCR、PDF 内容检索 | 维护成本较高，已有会话采集与 Markdown 导入，先后置。 |
| 数学公式、Mermaid 等语法 | 按实际内容选择，同时验证阅读、编辑和导出一致性。 |
| 关系图谱、无限画布、块嵌入、数据库看板 | 暂缓，避免提前改变内容模型与产品复杂度。 |
| 团队协作、社区、公开链接 | 不纳入本项目。 |
| 音视频播放、复杂文档预览 | 继续采用普通附件保存和下载。 |
| 与 Obsidian 共用并同时编辑内部资料目录 | 不做，通过导入导出交换资料。 |

## 架构、风险与回退

React 和 CodeMirror 继续承担界面与编辑；稳定笔记 ID 支持收藏和关联，不可变修订支持历史恢复，现有多选与保存流程支持批量整理。没有理由仅为对齐竞品重写存储。

搜索和反向链接索引可作为本机可重建数据，不随 Git 同步。当前部分读取流程扫描修订文件，先用不同数量的笔记和历史修订测量响应，再决定是否加入缓存或增量索引。现有数量限制不是性能验收结论，不提前引入数据库。

| 范围 | 可能影响的模块 | 风险与控制 |
| --- | --- | --- |
| 查找与界面 | `src/client/`、`src/notes/search.ts`、查询契约 | 搜索结果和翻页一致性、快捷键与宿主冲突；保留已有搜索流程，验证中文、长文、筛选组合。 |
| 收藏、批量整理、历史恢复 | `src/contracts/notes.ts`、`src/notes/repository.ts`、修订及同步、对应界面 | 新元数据是否同步、批量部分完成、旧版附件完整性；沿用修订与当前版本检查，避免覆盖其他内容。 |
| 会话关联 | 客户端宿主扩展、来源资料和关联契约 | 公共接口可用性、其他侧栏共存、跨设备原会话缺失；先验证，不承诺未验证能力。 |
| AI 输出 | 宿主模型接口、选材和结果保存 | 材料范围、结果可靠性及消耗；用户主动选择、预览采用、保留来源。 |

每批具体协议和配置改动在实施方案中列明。一般代码回退使用新回退提交；如需要变更数据格式，先安排匹配的数据备份及回退说明，不能只降级包后继续写新版数据。不另建庞大兼容框架，不重写 Git 历史。
