# 0.9.0 发布前准备

状态：2026-11-16，发布准备已完成，具体候选与结果见[发布审核](../releases/0.9.0/review.zh.md)。用户要求“现在准备发布新版”，据此完成本机准备和正常提交推送；GitHub Release、标签和市场 PR 等待本轮最终发布确认。

## 目标与范围

将公开 0.8.0 后已经批准、开发和体验的改动合并为 **0.9.0**：会话侧栏与关联、选材转存及引用、文件接收与同步性能、阅读和导出、界面主题与设置、用户手册、列表组织与新品牌，以及 DSH 0.2.2-rc.3 适配。

采用次版本号体现这次功能规模与升级边界。保留 package 名 `dsh-fatfish-notes`、测试仓库和已有发布流程，不新增功能、不更换依赖。用户本轮已排除刚提出的宿主机会；删除对应当前文档和候选链接，不加入发布范围，不重写 Git 历史。今后宿主更新的通用检查规则保留。

## 分轮工作

1. 核对 main、公开版本和原市场条目状态，冻结范围；本轮基线 `d2773b1`。
2. 将包及锁文件项目版本更新到 0.9.0；整理中英文 README、升级说明、精简发布说明和市场条目/PR 材料。准备阶段公开下载链接仍指向已发布 0.8.0，明确新候选尚未公开。
3. 用实际隔离界面刷新产品截图。优先使用已批准的用户手册及开发说明，不放入临时验收命名、无关文件或日常个人资料；截图反映真实运行效果。
4. 按第三档完成类型检查、构建、全量回归、打包与安装文件核对。用真实公开 0.8.0 存储实现生成旧资料，再用 0.9.0 验证正文、资源、历史、旧模板和空库升级；核对旧版拒绝新版清单的回退边界。
5. 最终候选实际安装到原隔离 Desktop；检查主界面、独立窗口、侧栏，保存后的双窗口刷新、普通/长文切换及笔记本切换，指定私库同步与重启读回。已有本日 rc.3 转存、引用、导出、图片批次等验证按相同运行代码复用；如构建比较显示业务代码改变，补相应回归。
6. 准备包、摘要文件、发布说明、市场更新材料、发布审核记录与体验入口。提交并推送 main，停在正式发布确认前。

## 影响、风险与恢复

主要改动为 package.json、package-lock.json 的项目版本、README、发布文档、当前入口及展示截图。`lib/` 由构建生成，业务源码应与已验收 rc.3 候选一致。

公开 0.8.0 使用 rc.1；0.9.0 以 rc.3 为宿主基线。新写入可使用 notes manifest v3/v4（显式补充资料采用 v4），同一私库各端需要一起升级；旧模板在新版作为普通笔记保留。保留公开旧包和隔离资料/配置备份，不覆盖用户副本。回退不能只装旧插件继续写新资料；需配套宿主与升级前资料备份，并另行确认恢复范围。

截图和说明必须区分当前候选与旧发布包。新包检查不含日常 DSH，不发送付费模型请求；不承诺 macOS、两台物理设备或大型真实资料库实测。

## 性能与验证口径

在同一隔离资料、窗口尺寸和操作口径下抽查普通/长文打开及笔记本切换，各至少五次，记录有效笔记数、中位和最大；首次加载如仅一次明确注明。保存双窗口刷新核对内容和版本，不把网络同步状态与本机保存混为一谈。

发布准备是一轮收尾，预计包含文档与截图、离线回归、旧版升级和实际宿主验收。过程发现产品问题先记入本规划：兼容修复若超出准备范围，再按项目规则讨论，不借发布新增未批准功能。
