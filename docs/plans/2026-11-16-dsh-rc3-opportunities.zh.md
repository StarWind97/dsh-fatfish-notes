# DSH rc.3：兼容、优化与新机会评估

日期：2026-11-16。对应[本轮适配与验证](2026-11-16-dsh-rc3-compatibility-check.zh.md)，纳入[产品主规划](2026-11-09-product-iteration-roadmap.zh.md)。

用户已批准 rc.3 适配及扩展更新检查规则。下列新增能力是候选建议，不属于本次实现范围，也不改变此前暂缓 AI 写笔记、网页导出等取舍。

## 检查原则

今后每次升级，同时回答三个问题：宿主变化对现有功能有什么利弊；哪些已有实现可以变得更简单、更快或更好看；是否出现此前未规划的新用途。不能只检查旧接口还在，也不能因为宿主提供了接口就认定用户需要对应功能。

证据依次区分：官方说明、当前安装版本的公开类型、内部实现、实际操作。建议说明用户任务、接口边界、价值、成本、风险和最小验证；缺少公开合同或尚未实测时明确标注。候选获用户选取后另落实施规划。

## 本轮变化及现有功能影响

| 宿主变化 | 现有功能的利弊 | 本轮处理及后续机会 |
| --- | --- | --- |
| rc.2 文档级文件粘贴 | 用户在会话内接收文件更方便；侧栏和正文必须正确取得事件，否则可能重复上传或进入错误区域。 | 核对宿主尊重 defaultPrevented、跳过输入框/contenteditable，实测正文与补充区接收、侧栏不串到会话输入框。沿用现有局部事件归属，无需增设全局拦截。 |
| 主题覆盖、浮层定位、侧栏固定与顺序 | 有助于宿主整体一致性；浮层、窄窗口和缩放是回归重点。 | 插件自有菜单没有使用发生变化的宿主定位服务；实际检查窄窗口与缩放边界。侧栏排序交给 DSH，不重复开发插件专用排序。样式与字体继续共享，侧栏明暗始终跟随 DSH。 |
| 历史消息分页及会话读取变化 | 长会话可逐步读取；不完整分页、截止点变化可能使转存漏消息或顺序错误。 | 插件已有固定截止点和分页读取，相关合同仍可编译，实际复验旧会话转存。不能只因新增分页就重写既有读取路径；超长会话选择速度如有新瓶颈，再测量后优化。 |
| rc.2 修复反复启动积累认证信息 | 减少宿主启动失败及手工清理的需要。 | 正常启动已验证；未制造大量 Cookie 或长期反复启动，不能承诺长期缺陷完全消失。不加入插件自动清理宿主认证缓存的机制。 |
| rc.3 Windows 更新修复 | 有利于宿主更新可靠性，不改变笔记存储格式。 | 核对真实桌面版本及插件运行结果；没有复演安装器更新全过程。 |

## 可选的新用途

工作量是下一轮试验的粗估，不是交付承诺；不包含公开发布、跨平台验收或复杂异常补齐。

| 方向 | 具体用途与建议 | 可用基础及限制 | 最小试验、成本与优先级 |
| --- | --- | --- | --- |
| 导入历史会话后整理为笔记 | 用户把 DeepSeek 网页/App 的旧讨论导入 DSH，再用现有选材转存保存为开发记录、学习资料或项目说明。优先复用宿主导入，不另造导入器。 | rc.3 官方提供实验性会话导入。现有笔记转存读取宿主会话，但本轮未使用用户导出档案测试导入消息、图片和附件的完整性。不能宣称所有历史附件都能恢复。 | 用一份人工构造、格式符合宿主要求的导出样本，检查文字、代码、分支及缺图提示；约半天至一天。**优先评估**，可能只需验证与简短指引即可形成新用途。 |
| 多代理任务的项目记录 | 当用户让多个代理研究或开发时，显式选择主会话及某些子会话，将问题、结论和交付资料汇成一篇可追溯的笔记。 | 新版支持命名及多级子代理，公开地址包含父子会话身份；仍需验证各级历史读取、权限和文件归属。现有原始素材属于单一会话，直接扩展会触及来源模型与存储，不能伪装成小按钮改动。 | 先验证两级会话、重复文件与明确的来源标记；试验约一至两天，正式方案另估。**中期候选**；必须用户选材，避免扫描所有子会话。 |
| 会话中的笔记引用卡片 | 让用户在聊天中看到一张简洁卡片，包含笔记标题、摘要和打开入口；减少长路径或读取提示词的视觉负担。 | 新版公开了 Markdown 代码围栏扩展位置，可作为渲染试验入口；它不是任意文本/链接都能自动变成卡片的接口。卡片也不等于文件已成为原生输入附件。 | 用一个明确的专用围栏演示单卡片，只读取允许访问的笔记；检测复制、转存及插件未安装时的文本退化。约一天试验。**可选探索**，先看实际效果是否比现有引用更清楚。 |

## 仍未达到接入条件的方向

**输入框原生附件**仍应每次必查。本轮 rc.1/rc.3 对比中，IConversation、SessionInput 和 InputActions 的公共成员清单未提供接收 File 并登记有效草稿的完整动作。addAttachments 接收已有草稿标识，不能代替创建草稿；createDrafts 在具体实现，ComposerBarInjected.addFiles 明确标为 Package-private。

因此继续使用现有引用流程；不调用内部对象、不伪造草稿 ID。未来需验证完整链路：文件接收 → 草稿登记 → 放入指定会话输入框 → 显示/移除 → 用户发送 → 模型可读取。具备公开接口及实际证据时，主动提示用户“条件已经具备”，再确认优化范围。

**动态 MCP 管理**可在宿主中注册、移除或查询服务，但并不自动给会话 AI 增加读写本插件笔记的权限和工具。用户此前已决定暂缓 AI 写笔记，本轮不因此重启这项开发；若将来讨论，仍需单独解决授权、并发编辑、冲突和可撤销修改。

## 建议顺序与来源

先交付当前版本兼容性；新增用途优先验证“历史会话导入后转存”，因为能复用既有功能，改动和维护成本较小。多代理归档与引用卡片留待用户确认真实使用需要后试验。仅因接口存在而新增设置、按钮或后台扫描，没有足够价值。

主要依据：[官方 rc.2 发布记录](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.2)、[官方 rc.3 发布记录](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.3)，以及本机实际宿主 rc.3 的公开类型和实现。输入与会话类型对比记录位于忽略目录 `.dsh-home/pure-001/compat-rc3-20261116/interface-audit.json`，实际验收边界统一以本轮适配记录为准。
