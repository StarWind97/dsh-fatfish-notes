# 肥鱼笔记 0.9.2 宿主兼容范围与隔离候选

2026-11-18。0.9.2 隔离候选已通过 rc.3 Desktop、rc.4 Web 实际验收。用户随后批准正式发布并提交市场更新，要求区分平台实测边界，公开后复核下载、安装和市场状态。开发基线为 `82206ba`，已验收候选提交为 `552d0e0`。

## 目标与方案

让 0.2.2 系列的用户可以提前更新同一个肥鱼笔记包，宿主在该系列内更新时正常通过安装和启动检查。`engines.dsh` 和 15 项需要共享宿主实例的 DSH peer 已设置为 `>=0.2.2-rc.3 <0.2.3-0`。它接受 rc.3、rc.4 以及后续 0.2.2 候选与正式版，排除更早版本及下一补丁系列。构建、类型检查与锁文件中的具体依赖解析继续使用已固定的版本。兼容范围与平台实测记录分开维护。

仅列 rc.3、rc.4 两个精确版本可以缩小已声明范围，但下一个同系列候选仍会因版本号变化被挡住。选择有上限的范围，并在同系列更新时核对实际接口变化；到了 0.2.3 或发生破坏性接口变化，再评估适配。依据：[DSH 官方打包指南](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.4/docs/user/develop/basic/publish.zh.md#L66)、[rc.4 加载判断](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.4/packages/boot/app-boot/src/plugin-compatibility.ts#L51)。

影响限于 `package.json`、锁文件根元信息、候选说明和项目验证记录，以及必要的项目内隔离体验脚本。现有业务、UI、存储格式、身份校验和同步协议沿用 0.9.1，公开安装入口继续指向 0.9.1。若发现需要额外修改业务行为或升级系统宿主，先报告并重新确认。

## 验证与交付

1. 核对范围边界、开发依赖及业务代码差异。按发布候选第三档运行类型检查、构建和全量回归，打包并记录 SHA-256、清单和与 0.9.1 的文件差异。两套宿主安装使用同一个固定包。
2. Windows rc.3 使用项目既有隔离 Desktop，先确认已安装 0.9.1、指定测试库身份与同步状态，保留安装信息及 0.9.1 包。走实际现有配置升级到候选，核对安装文件、三入口、已有笔记、保存与跨窗口刷新、同步和重启读回。
3. 用 npm 的固定 rc.4 宿主启动项目内隔离 Web，验同包安装、加载、宿主访问、已有笔记、新建或编辑保存、同步和重启读回。真实同步仅用 `StarWind97/dsh-community-private-test`，校验 ID `1440762952` 和私有性。必要时使用独立 Web 资料承接本地副本。Windows rc.4 桌面、市场真实升级留到官方桌面包和发布阶段。
4. 发布候选响应抽查沿用实际入口，覆盖打开普通/长笔记、切换笔记本和双窗口刷新。桌面阅读与切换各 5 次，按目标内容可见并绘制完成计时，记录资料规模、中位及最大；一次双窗口刷新时长只用于确认交互。
5. 交付候选包、摘要、验证报告和可重开的桌面/Web 隔离入口。停掉为验收新启动的进程。按项目约定提交后推送，核对远端 SHA。公开 Release 与市场条目保持当前状态。

主要风险是范围内新宿主改变接口、安装器实际解析了错误的 peer 副本，及升级过程中覆盖测试资料。安装前留存隔离配置、验证资料归属和写入状态；需要回退时在 rc.3 隔离环境重新安装原 0.9.1 包，保留笔记资料和旧标签，新改动以普通回退提交撤销。预计一轮包声明和构建，一轮双宿主安装与真实验收。
