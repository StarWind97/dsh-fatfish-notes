# 工作区笔记本原地操作与取消新建返回修正

2026-11-12 用户批准实施，现已完成，见[交付与验收](2026-11-12-sidebar-inline-actions-results.zh.md)。属于 E 集中验收修正；不发布新版、不启动 F。

## 已确认的交互

- 工作区设置初始只展示当前笔记本及操作入口；点击铅笔在名称原位置编辑。
- 「使用已有笔记本」改为「选用其他笔记本」，点击才展开选择框；「新建笔记本」点击才展开名称输入框。
- 三种操作都在对应字段旁使用同样的 ✓ / ×，提供悬浮提示和无障碍名称。分别为保存名称/取消改名、确认选用/取消选用、创建并关联工作区/取消新建。普通新建入口未选关联时为创建笔记本。
- ✓ 提交当前操作，成功后退出行内编辑；工作区设置保持打开。× 或 Esc 放弃当前未确认输入，返回普通设置。普通状态 Esc、右上关闭及底部关闭才关闭弹窗。已确认的改名不随之后取消其他操作回退。
- 只展开一项操作；中文输入法确认文字不触发提交。忙碌时禁止重复提交与关闭，失败保留输入供重试。
- 侧栏取消新建笔记回到原列表，保留选项卡、笔记本、搜索/来源筛选及滚动位置；取消已有笔记编辑留在其阅读态。草稿丢弃失败仍停在编辑器。

## 原因与取舍

旧设置把改名输入放到下方，Esc 直接调用整窗关闭。侧栏新建又提前切到关联分组，取消只清空草稿，未清除正文展示状态，使列表出现但筛选更新被阻止。实测两篇关联笔记在取消后显示零篇，点后退才重新出现。

采用局部原地操作及按实际正文可见性协调导航，不新增路由或存储模型。统一同类小操作的界面语言；本轮不重做整个插件的所有表单、危险操作或笔记管理页面。

## 实施与验证

影响 `WorkspaceBookDialog`、`PaperDialog` 的可选 Esc 回调及 `ConversationNotes` 的展示/返回状态；沿用笔记本和草稿接口，不改保存、同步、身份协议或依赖。

按第二档运行类型检查、构建、相关客户端测试，增加真实组件交互回归覆盖两处遗漏；隔离 DSH 检查改名接受/取消、两级 Esc、选用/新建及失败保留、空白/有内容草稿取消、已有笔记取消、列表滚动和筛选保留。仅使用既定隔离资料与指定私库；验收不改日常资料。

性能重点为恢复已加载列表，不重复全库扫描或等待云端；比较同一列表取消后恢复位置，复用既有数据。此轮不更改读取缓存或运行全量基准。

局部小批次交付：代码、相关验证记录、截图及更新后的体验入口。主要风险是 Esc 误关闭其他弹窗、取消失败仍离开编辑、笔记本创建成功而绑定失败；通过局部回调、成功状态判断及保留已创建本重试覆盖。回滚用回退本次代码提交并重装隔离旧包，数据格式无需迁移。
