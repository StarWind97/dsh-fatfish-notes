## 确认后如何发布

1. **Agent** 核对本地材料与审核版本一致，将材料提交并同步至 `main`，设置仓库简介与主题标签。
2. **Agent** 创建 `v0.5.0` 标签和正式 GitHub Release，上传上述安装包及校验文件；核验匿名下载、文件校验和安装来源。若包内容需修改，重新核对材料与必要验证后再上传，不悄悄替换已审核内容。
3. **Agent** 按收录项目当时的规则，只新增上述 YAML 文件并发起 PR，使用已经审核的申请正文。此时状态为「申请处理中」，不是「已上架」。
4. **Agent** 查看自动检查和维护者反馈，修正文案等收录问题。若要求新增功能、扩大权限或改变发布方式，先与用户讨论。合并后再核对市场实际展示。
5. **用户** 负责本页内容的最终确认，以及确有需要时的浏览器登录、验证码或账号验证。现有 GitHub 认证若仍有效，普通发布和 PR 操作由 Agent 执行，无需用户手工输入命令。

审阅阶段材料保留在本机，未提交推送或对外发布。现在按用户批准的范围执行上述步骤。代码仓库在材料准备开始时已经公开；本轮无需更改其可见性。
