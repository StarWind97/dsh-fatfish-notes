## 市场问题与反馈

1. [#1147：Release 安装未关联条目，发现页仍显示安装、已安装页缺少简介](https://github.com/dsh-market/dsh-market/issues/1147)。使用市场 1.73.15 实际代码复现：Release URL 的安装身份为空，友好显示名称与技术包名不匹配，因而找不到用于展示简介的条目。建议仅修复展示关联，保留严格的安装与来源授权判断。
2. [#1148：GitHub 声明读取失败时显示宿主要求未知](https://github.com/dsh-market/dsh-market/issues/1148)。0.6.0 的公开 manifest 已声明 DSH 0.2.2-rc.1。同版本原始模块探测在不设进程代理时得到 ECONNRESET/unknown；只为测试进程配置可用代理后得到 HTTP 200/compatible。真实隔离 DSH 通过实际公开 catalog 查询也返回 `compatible`、要求 `0.2.2-rc.1`。

无进程代理的完整宿主查询包含 catalog 读取，在 60 秒内未完成；不将它归因于单独的 raw 请求。用户原始截图那次网络响应不可追溯，本轮证实的是可重复的声明读取失败路径。两项反馈均已提交并回读确认为 OPEN，不宣称市场维护者已经修复。0.6.1 的依赖修正不会自行解决市场的条目关联或网络读取问题。

## 隔离实例启动弹窗

本轮反复启动期间出现 `desktop welcome: Web authentication failed`。在隔离 Electron 进程中只记录本机请求路径和状态码，确认首次 Node 认证请求返回 303，随后 Electron 请求返回 **431**。该实例累计 71 个 `dsh-auth-` 本机认证 Cookie，仅 Cookie 请求头已达 16,186 字节，加上其他头部超过宿主限制。

仅清理已校验身份的 `release12-shell` 内 `127.0.0.1` 的 `dsh-auth-` Cookie，之后启动及关闭重开均通过。未重置笔记、GitHub 认证、模型账号或日常 DSH，也未修改宿主安装文件。此为宿主本机认证 Cookie 积累问题，不是 GitHub 登录失效；本轮恢复隔离实例，未替宿主实现永久清理机制。留待单独向宿主反馈，不扩大本轮市场反馈的接收范围。
