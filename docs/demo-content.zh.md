# 示例笔记与产品展示内容准则

2026-11-15 用户明确要求，后续制作示例和产品介绍时持续采用。

- 开发手册中的工程示例优先使用开发技术资料、操作说明、调试记录、设计取舍和项目整理场景。对外展示按下文的留存价值、熟悉感和兴趣标准选题。问题、输入、步骤、结果之间应有真实逻辑，读完能获得信息。
- 标题、摘要、标签与正文保持一致；整理标题层级、段落、列表、表格、代码语言、空行和图片尺寸。不用重复占位句撑长文，不堆叠“测试、示例、验收成功”等字样作为展示正文。
- 会话转存模拟自然的多轮工作过程：用户提出具体问题、补充约束，助手解释和修改。不能只有“请生成文件 / 已生成”等空泛回合；模拟素材不包装成真实客户记录、真实模型测评或实际工具执行证据。
- 对外展示采用有代表性的内容和真实产品截图，注意文字密度、留白、阅读顺序与图片质量。不以生成的 UI 假图替代真实功能，不夹带账号、凭据或私人内容。
- 可以调用 GPT 生图制作美观配图；技术机制图应保证文字与关系准确。配图服务于内容，不给每篇文章强加装饰图，不使用无法辨读的假代码或乱码画面。
- 补充附件可为示意内容，文件名、扩展名与大小应合理。大小来自文件本身；优先提供能正常打开的 PDF、CSV、Markdown、代码或 ZIP，不用空壳冒充可用文档。
- 工程边界测试和对外展示素材分开维护。已有回归资料可保留，但展示入口优先指向整理后的内容；不覆盖用户临时编辑的笔记。
- 发布页、市场截图和正式宣传仍按发布授权处理。隔离候选的素材质量改善不代表允许对外发布。

手册分工：开发手册服务开发者与维护者，用户手册服务使用者；用户册既教操作，也用实际笔记演示表达。初始化只提供用户手册，保留默认笔记本作为日常收集入口。用户的修改、改名、移动与删除不被后续版本覆盖或自动补回。

当前整理接续[示例内容规划](plans/2026-11-15-demo-content-refresh.zh.md)，按[两本手册与首次使用体验规划](plans/2026-11-15-handbooks-onboarding.zh.md)推进。配图源与提示词见 [用户手册素材说明](../assets/handbook/README.md)。

## 视觉质量与发布展示验收

2026-11-16 按用户确认的[三方向评审规划](plans/2026-11-16-showcase-visual-review.zh.md)补充：插件界面和对外展示的美观程度与功能同为交付条件。功能通过后独立检查内容、主题搭配、信息密度与取景，不能以“真实截图”代替视觉验收。

- 展示可主动切换更合适的正式主题、配色和字体，不必只拍默认状态；保留原偏好，实际效果可由正常设置重现。
- 展示笔记应构成连贯、自然的工作场景，列表不只有一条，正文有实质信息与合适的图文结构；避免为凑满画面增加空泛文字。
- 对外展示先确认内容有真实的留存、查找与复用需求，再选择大多数目标用户熟悉、愿意了解的主题，让人看懂“我也可以用它做什么”。技术资料与使用说明服务该场景，不优先选容易编写但用途狭窄的技术题目，也不因某个成果容易做得漂亮就牵强地安排笔记用途。
- 图片、字体、代码和目标列表必须在最终取景后重新检查，不能只等固定时间或以零个图片元素通过加载断言。
- 原尺寸和 README／市场实际展示宽度都要人工查看，检查层次、清晰度、留白、遮挡、截断与完成状态。设置能力优先用实际效果说明，不让空表单占据主要宣传位置。
- 本地候选与公开展示分开。候选进入忽略目录；确认后才更新公开索引或已有展示引用，旧版本保留可回溯。
